# §S item 3 — Q8, exercised: the order ask, driven to Upkeep for real

**Claim the brief asked to settle**: drive the game to Upkeep (a loop that
passes until Upkeep and reads the stack before answering), with two
simultaneous triggers; real-Forge test: no ordering ask without Full Control,
one with it; revert the rule and the first fails.

## Why w33 never got here, exactly

`wave33-evidence/s3-blockers.md`'s "Q8" left two designs inconclusive: a
synthetic `activephase=UPKEEP`+`activephaseadvance=UPKEEP` jump (no triggers
materialise — `GameState`'s phase-advance has no equivalent of
`handleCombat`'s `addAllTriggeredAbilitiesToStack()`), and driving
`two-triggers.state` (TWO Dark Confidants) through ordinary priority passes —
life never dropped, and it was left open whether that was the scenario or the
drive loop.

**It was neither.** Traced to Forge's own source:
`PlayerControllerHuman.orderSimultaneousSa` (`PlayerControllerHuman.java:2243-
2271`) only prompts for an order when the simultaneous abilities' own
`toString()`s differ, or a trigger carries `OrderDuplicates$ True`:

```java
boolean needPrompt = !activePlayerSAs.get(0).isTrigger();
...
if (currentSa.isTrigger()) {
    needPrompt |= currentSa.getTrigger().hasParam("OrderDuplicates");
} else if (currentSa.usesTargeting()) {
    needPrompt = true;
}
if (!needPrompt && !saStr.equals(firstStr)) {
    needPrompt = true;
}
```

Two Dark Confidants are the IDENTICAL trigger text twice (`isTrigger()` true,
no `OrderDuplicates`, `saStr.equals(firstStr)` true) — `needPrompt` never
becomes true, and Forge silently keeps its own queued order with **no `order`
call at all**, which is also why life never dropped: not a broken scenario, a
real-rules no-op Forge is entitled to take for two mechanically-interchangeable
triggers. Confirmed directly, under BOTH policies (default and full control):
driving two Dark Confidants to Upkeep produces exactly two `getAbilityToPlay`
asks (one per source — the generic "materialise this mandatory trigger" step,
same mechanism as a normal cast) and **never** a method `'order'` ask, in
either mode.

## The fix: a scenario with two DIFFERENT upkeep triggers

`apps/server/src/play/scenarios/two-triggers.state` now pairs Dark Confidant
with Phyrexian Arena — two different upkeep triggers, same controller, same
timing, whose `toString()`s differ, which DOES hit `needPrompt = true`.
Everything else about the scenario (landing in the opponent's Cleanup Step,
driving Cleanup → Untap → Upkeep through ordinary priority passes/asks, never
a synthetic phase jump) is unchanged from w33's second design — the design was
fine; the deck in it was not.

## The drive loop

`scenario-order.jvm.test.ts`'s `driveToUpkeepWithBothTriggers` presses OK on
every `Priority:` stop for EITHER seat as Forge offers it (never a blind
"press everything"), and stops the INSTANT `s.phase(0) === 'Upkeep step'` AND
`/Stack: 2 to Resolve/.test(s.prompt(0))` — i.e. it reads the stack at Upkeep
before doing anything else, exactly as asked. `s.answerAsks()` runs every tick
so `getAbilityToPlay`/`getChoices` asks unrelated to the ordering claim don't
stall the drive, but the order ask itself is captured through a `reply` hook
that records every ask BEFORE any default answer is computed, so its presence
or absence on the wire is observed directly, not inferred.

## The real-Forge measurement

| policy | raw `order` ask ever reaches `s.sent`? | server log |
| --- | --- | --- |
| `DEFAULT_STOP_POLICY` (`orderSimultaneous: 'forge'`) | **no** | `ask-auto-answered`, `method: "order"`, `why: "Forge's own order"` |
| `FULL_CONTROL_POLICY` (`orderSimultaneous: 'ask'`, via `Match.setFullControl(0, true)`) | **yes** — `{"method":"order","title":"Select order for simultaneous abilities","sourceChoices":[…2…],"showRememberCheckbox":true}` | no `ask-auto-answered` for `order` |

Both asks are the SAME shape Forge offers for this exact situation
(`lblSelectOrderForSimultaneousAbilities`, `PlayerControllerHuman.java:2313`).

## Mutation test

`DEFAULT_STOP_POLICY.orderSimultaneous` reverted from `'forge'` to `'ask'` in
`apps/server/src/play/auto.ts` (simulating "the Q8 rule does not exist"):

- **Reverted: 1 failed / 1 passed.** The default-policy case fails exactly as
  predicted (`an order ask reached the client under the default policy:
  expected true to be false`); the full-control case is unaffected (full
  control already forces `'ask'` regardless of the default).
- **Restored: 2 passed / 2 passed.**
