## Settled — do not re-open

- **A room's game is `gameType` plus the game's blob in `game`** (plan, phase 3). Magic's blob is
  `MagicRoomGameSchema` (`magic-room.ts`). The platform base (`roomBaseFields`) never names a Magic field.
- **Nothing a player sees changes.** No release note for items 1 and 2. A room renders identically, before and
  after, in every state the e2e covers.
- **No open tab breaks across a deploy.** Nothing reloads a tab when the server's bundle changes. An open tab keeps
  its old bundle, and its old schema `.catch`es a missing field to a default: an empty format, Classic mode, no pod.
  So the copies are deleted **only after a prod release carrying item 1 is live**. That's what makes item 2 a
  separate land with a gate (below).
- **Saved rooms are untouched.** Storage is `room/lobby-codec.ts`'s codec v2, which already stores Magic's part as
  `game`. `room/codec.test.ts` stays byte-identical.
- **The layer fence holds.** `scripts/layers/ratchet.test.ts` is key-strict since w99. No new edge. Ratchet keys
  carry no line numbers, so a rewrite inside a file never trips it.
- **Tests are rewritten, not weakened.** Moving a read from `room.format` to `room.game.format` is mechanical. Do it
  with a codemod (a `ts-morph` or `jscodeshift` script under `/home/hadoku/lane-scratch/w100/`, never committed).
  Every test asserts the same values after as before. Report per file: assertions before and after
