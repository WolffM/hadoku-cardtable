## §A — The art source, and why this is the lane that matters

The operator: *"there's a good chance i source the art from somewhere else in
the future… just make sure that it's easy to simply hook up a link to a new
image in the cdn whenever that happens."*

So the deliverable is **not** "URLs that point at our CDN". It is an
**indirection** where a card's art is a lookup that can be repointed per card,
without touching rendering code.

1. An art manifest: `scryfallId` → art entry. Committed JSON, so repointing one
   card's art is a **data edit** reviewable in a diff.
2. An entry names its **source** and its **key**, not a bare URL, e.g.
   `{ "source": "cdn", "key": "<sha256>.jpg" }` and
   `{ "source": "scryfall" }`. A resolver turns an entry into a URL. Adding a
   future source (`"source": "custom"`, a commissioned illustration, a different
   licensor) is then a new arm in one function plus manifest rows — never a
   change to a component.
3. **A missing entry must fall back, not fail.** An unlisted card falls back to
   Scryfall, and a card with neither falls back to the text tile. Both already
   work; keep them working.
4. Keep the manifest **separate from `pool.json`**. The pool is regenerated
   wholesale by `build-pool`; art assignments are hand-curated and must survive
   that. A regeneration that silently discarded custom art would be exactly the
   kind of quiet loss this repo keeps finding.
5. Done when: the manifest and resolver exist with tests covering all four cases
   (cdn entry, scryfall fallback, no-art fallback, unknown source); and a test
   proves **repointing one card to a different key changes only that card's
   URL** — the swap requirement, asserted rather than asserted-to.

## §B — Upload the art to `cdn.hadoku.me`

`@wolffm/cdn-client` exists (`createCdnClient`, `MAX_UPLOAD_BYTES` = 10 MB) and
the upload route is `hadoku.me/cdn/api/upload`, friend+. The CDN is
content-addressed by SHA-256, so an upload is idempotent by construction and
re-running the CLI must be safe.

1. A CLI: read the pool, fetch each card's art **from Scryfall**, upload to the
   CDN, write the resulting key into lane A's manifest.
2. **Rate-limit the Scryfall fetches.** Their guidance is 50-100 ms between
   requests; 534 cards at 10/s is about a minute. A burst of 534 parallel
   requests is how a project gets blocked, and being blocked is how the whole
   feature fails at the worst moment.
3. **Idempotent and resumable.** Skip a card whose manifest entry already
   resolves. The run must survive being interrupted and restarted.
4. It needs a friend-tier credential to upload. If none is available in the
   environment, **stop and report** — do not invent an auth path, and do not
   write a token into the repo.
5. Report at the end: uploaded, skipped, failed, and total bytes.
6. Done when: the CLI is idempotent (a second run uploads 0), the manifest is
   populated for every card that has art, and the closing note carries the
   counts. **If the credential is unavailable, the lane still lands the CLI**
   and reports that the upload did not run — say so plainly rather than
   implying it did.

## §C — Render from the art source

1. `cardImageUrl` becomes a thin call into lane A's resolver. Keep its current
   guarantees: returns `null` rather than a broken URL, and the text tile is
   always the fallback.
2. **Keep the aspect-ratio rule.** `.card:has(.card__art)` pins the tile to
   488/680 so `object-fit: cover` crops nothing. That was a licensing rule when
   the art was Scryfall's; with our own CDN it stays because a cropped card
   still looks broken.
3. Rewrite the D13 tests for the new posture. The old ones asserted "every URL's
   origin is cards.scryfall.io" — now `cdn.hadoku.me` is legal too, and
   **same-origin is still not**: we serve the app, not the bytes.
4. Done when: the UI renders from a CDN entry, from a Scryfall fallback, and
   from no entry at all; and the tests assert the **allowed hosts** rather than
   a single one.

## §D — Rewrite the rules to match what we now do

The repo currently says, in four places, that we never host card images. We are
about to host card images. **Leaving those words next to this code is worse than
either choice alone** — the next session reads them and either breaks the
feature or distrusts the docs.

1. `docs/LICENSING.md`: rewrite rules 2-3 and §3.1. **Keep the reasoning
   trail** — do not delete the old argument. Record what was believed, that the
   operator decided otherwise, and on what grounds (no money, private, friend
   gate, art treated as a replaceable placeholder). A rule that changed without
   a recorded reason is one that flips back.
2. `CLAUDE.md`: the "Critical rules" bullet and the "Does NOT" list.
3. `docs/DECISIONS.md`: a new decision superseding D13's image clause, dated,
   attributed to the operator. Do not edit D13's text — supersede it, the way
   this log already handles every other reversal.
4. `NOTICE.md`: check whether the disclaimer needs strengthening now that we
   host art rather than link it.
5. `.github/workflows/ci.yml`: the D13 gate. It currently fails on any host that
   is not `cards.scryfall.io`. It must now allow `cdn.hadoku.me` **and still
   fail on a same-origin or relative image URL** — we host on the CDN, never
   from the app's own origin. Mutation-test both arms and quote the counts.
6. Done when: `grep -rn "never.*host.*image\|Never commit or host card images"`
   over `docs/` and `CLAUDE.md` returns only text that is explicitly historical,
   and the CI gate's new arms are mutation-tested.
