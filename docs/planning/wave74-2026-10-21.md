## Wire contract — E adds to `packages/shared/src/pool.ts`

```ts
export const SetSummarySchema = z.strictObject({
  code: z.string(), name: z.string(), date: z.string(), type: z.string(),
  cards: z.number().int().nonnegative(),          // non-basic singletons (set-cube size)
  verdict: PoolVerdictSchema.nullable(),          // null = not yet checked at this Forge pin
});
export type SetSummary = z.infer<typeof SetSummarySchema>;

export const DraftPresetSchema = z.strictObject({
  id: z.string(), name: z.string().min(1).max(60), plan: DraftPlanSchema,
  createdBy: z.string(), createdAt: z.string(),
});
export type DraftPreset = z.infer<typeof DraftPresetSchema>;
export const SavePresetBodySchema = z.strictObject({ name: z.string().min(1).max(60), plan: DraftPlanSchema });
```

`PodView.planName` becomes the plan's display name:

- three equal rounds give that source's name, e.g. `Innistrad · Realistic`;
- otherwise the round names are joined with ` / `, e.g.

## Settled — do not re-open in any lane

  template, quirks included. Never a TypeScript re-implementation of rarity

  list.
- **Sets** are every set Forge has a draft template for, searchable, newest
  first.
- **Presets** are named custom plans, shared with the group. The creator
  deletes (the same rule as cube imports; stated to the operator 2026-10-21).

## §E — set sources (server, long pole)

1. Commit the contract additions alone. Report them; the manager lands them.
2. Extend `deal` per round:
   - **cube**: as wave 73.
   - **set-cube**: the round's list is `forge.setCards(code)`, through the
     catalog for text. Rounds of the same set share one shuffled deck. Append
     a second shuffled copy only when that deck runs out (ruling 3).
   - **realistic**: packs are `forge.boosters(code, seatCount, seed + ':' + round)`,
     mapped through `catalog.byPrinting` (falling back to `byName`) so the art
     is the set's own printing.

   Pure where possible: realistic boosters are fetched before `deal` and
   passed in, so `deal` stays synchronous and seeded. The dealt packs persist
   in the pod snapshot (built in wave 73). A restore must not call Forge.
3. Set verdict, in `room/plan.ts`:
   - `unplayable` is `forge.check(setCards)` plus every name Forge's booster
     template can emit for that set, so the land slot and DFC slot are
     covered;
   - `missingText` is every name the catalog cannot resolve;
   - cache it per (code, Forge pin).

   Never a pass by default when Forge is down: refuse with the reason.
4. `pools/sets.ts`: `GET /api/pools/sets` from `forge.sets()`, cached per pin
   and sorted newest first.
5. Wiring commit (after G lands): mount presets and the refresh job in
   `index.ts`.
6. Done when:
   - Acceptance 2 is red-then-green;
   - `GET /api/pools/sets` on a jar-env local server lists ISD, ALA and ARB,
     with the count of sets in the report;
   - a realistic ISD pack from the real jar has a DFC, shown in a JVM test
     run with the jar env and a skip count of 0.

## §G — presets store + a catalog that keeps up

The Scryfall data under the catalog was synced 2026-09-15
(`packages/carddata/data/manifest.json`), so any later set has no card text and
every set source with a later card is refused for `missingText`. The deploy
chain lives in hadoku_site, so the refresh lives in this server.

1. `presets.ts`: `data/presets.json` (the same data dir as `data/cubes`),
   atomic writes, routes per the contract, creator-only delete.
2. `refresh.ts`:
   - once at boot plus every 24 h, read Scryfall's bulk listing (one paced
     request, the existing `fetchBulkListing`);
   - if `default_cards` is newer than the local manifest, download into
     `$CARDTABLE_SCRYFALL_DIR` (default `~/.local/share/cardtable/scryfall`,
     never the deploy tree), rebuild the catalog to a temp file, rename it
     into place, and `catalog.swap()`;
   - one run at a time, logged start/finish/fault;
   - a fault keeps the old catalog.

   Clear every cached verdict whose `missingText` was non-empty when the
   catalog swaps, so a set refused for missing text can pass after a refresh.
   Expose a clear function; E calls it from the verdict cache.
3. `catalog.ts`: add `byPrinting(set, collectorNumber)` and `swap(next)`.
   Readers hold the catalog object, not its map, so a swap is visible
   everywhere.
4. Done when:
   - Acceptance 3 is red-then-green;
   - a mutation test (make `swap` a no-op) fails the refresh test;
   - the report gives the time and peak RSS of one real local rebuild from
     the 2026-09-15 data. If it is over 2 GB, say so: the refresh then runs in
     a child process, not the server's heap.
