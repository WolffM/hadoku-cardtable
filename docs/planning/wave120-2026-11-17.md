Protocol: `docs/handoff/w120.md` carries it. One manager, one sub-agent per lane, all parallel, no shared files.
Implementers commit and stop. The manager verifies each lane from its artifacts, lands lane by lane, and calls a lane
landed only when PPE carries it (and, for lane P2, when the package is published).

## Why

w119 (closing note `~/.cache/cardtable-manager/w119-closing.md` and its four lane notes; read all five) landed the
room socket in game-server, the leader's three seat routes, the shared seat pieces, the generic room read and the
removal of bomberman's code. It left stage 1 short of the operator's rule "one shared implementation; each site deletes
its copy":

- `rooms-protocol`'s `SeatTable` cannot hold a CLOSED seat below an open one, which Magic's draft pods use
  (`POD_CLOSED`), so cardtable's `GameSeats` was not rebuilt on it. The three seat ops are cardtable's own copy
  (`packages/game-server/src/room/seat-eviction.ts` + `lobby.ts`), and a 1v1 room's seats (`TableSeats`) answer the
  three routes with 409 `not-draft`.
- U's remove control (`onRemoveMember` on `SeatList`/`PodSeats`) is built but unwired.
- The front-page module is only `LobbyShell`'s slots: `RoomList.tsx`'s generic list, filter and create dialog are
  still Magic's, so bomberman's site cannot import a room list.
- C left `MatchSpec`'s Forge fields, ArchiveBot, `playWorkDir` and the import-time `CONFIG` call.
- `land.sh`'s related-tests pass missed `apps/server/src/index.test.ts`'s route table and reddened main for 5 minutes.

Stage 2 (bomberman's repo, wave `bm1`) runs **at the same time** in its own repo and consumes this wave's lane F
through npmjs. F's module name and props are therefore fixed below and may not drift.
