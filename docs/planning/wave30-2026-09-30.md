t=0.** Implementers commit and stop; the manager verifies from artifacts and

  `@wolffm/task-ui-components`' `ConnectedSettings` is documented as the control

  try to inject into theirs, and do not file an upstream ask for it.

  `docs/planning/wave30-evidence/item1-mulligan-diagnosis.md` reproduced it

  them.

  fact, never a branch. `auto.ts`'s header states it.

## §A — One board, and a settings panel that is ours

**Item 11 — the board stops being type-separated.** The battlefield groups
permanents into `BOARD_ROWS` (`lands`, `artifacts`, `creatures`, `other`) and the
operator has asked three times for that not to be the default.

1. **One undivided battlefield is the default.** Cards sit where they are put;
   wave 24's placement model already does the rest — a drop on a card's top or
   bottom third stacks it, the middle reorders, a new permanent joins the end.
   That model is not being replaced, only un-bucketed.
2. **The type-separated view survives as the ALTERNATE**, behind the setting. It
   is not deleted: the operator asked for it as a choice, and several tests pin
   its markup.
3. Expose the choice as a PROP with `single` as its default, and read the stored
   preference beside it. Build both halves yourself — the prop is what makes this
   testable without the panel, and the panel is yours too.

**The settings panel.** Ours, in the live chrome, holding exactly two things this
wave:

4. *Board layout* — single (default) or type-separated.
5. *Always stop at end step* — default **off**. The control sends §B a message;
   you choose its shape and report it in your first message to the manager.
6. **Persist per viewer.** `@wolffm/prefs-client` is already an `apps/ui`
   dependency and is the fleet's preference service — prefer it to
   `localStorage`, which does not follow a player to another browser. If it
   cannot hold an app-scoped preference, say so and fall back, with the reason in
   the code.
7. The panel must be reachable during a match without covering the board while
   closed, and must not add a fourth floating thing to a screen that already has
   a rail, a control cluster and a log button.

**Three small ones, same files:**

8. **Item 9** — the graveyard is double-stacked; make it single.
9. **Item 5** — delete the `Leave` button. `Concede` is enough.
10. **Item 16** — delete the `Call Back` button. Know what it costs: it is
    Forge's own `lblCallBack` / `InputAttack.canCallBackAttackers()`, which
    un-declares attackers, so removing it removes that ability. The operator has
    asked for it anyway.

**One constraint on `adapter.ts`, which is yours.** Two tests pin it from
directories NO lane owns — `apps/ui/src/components/ManaPip.test.ts` and
`packages/carddata/src/art/ids.test.ts`. **Add to its exported shape, never
change it.**

## §B — The mulligan flag, and a stop you asked for

**Item 1 — the mulligan.** Read
`docs/planning/wave30-evidence/item1-mulligan-diagnosis.md` first; it has the
reproduction, the measured frame, and three hypotheses already eliminated.

1. **Find where `Mulligan` is lost, in this order**: the bridge's delta (dump the
   raw lines with `CARDTABLE_PLAY_DUMP=<dir>` and grep for it — if it is absent
   there, nothing downstream can fix it); then the server's projection
   (`visibility.ts`); then whether Forge sets it on the GameView the delta is
   built from. `packages/forge-wire` models it already
   (`tier-c.ts`, `Mulligan: 'BooleanType'`) and **is not yours** — if the wire
   model is the problem, stop and report.
2. **The test must drive a REAL mulligan.** The existing unit test passes because
   it synthesises the flag, and the only real-Forge mulligan coverage uses Serum
   Powder at the KEEP prompt and never reaches the London step. Put the new test
   in `apps/server/src/play/` (yours) — the probe beside the diagnosis shows how
   to reach the step: answer the coin toss, press `Mulligan` at the keep prompt,
   then read the Game object.
3. Budget: **at most three runs** to reproduce before you report what you have.

**Item 2 — the end step stops being a stop.**

4. Remove `END_OF_TURN` from `DEFAULT_STOP_POLICY.stopOnTheirTurn`. Keep
   `COMBAT_DECLARE_BLOCKERS`: the operator objected to the end-step wait
   specifically, and blocking is not a wait, it is a decision they must make.
5. **Keep the reasoning that put it there.** `auto.ts:301-305` records that with
   `skipNonStopPhases: 'always'` an empty `stopOnTheirTurn` leaves no window to
   cast a held instant. That trade is now the operator's, taken knowingly:
   full control is the escape, and the setting §A builds is the dial.
6. Accept §A's stop-preference message and move THAT SEAT's policy. The per-seat
   `StopPolicy` already exists (wave 26 §E) and `Match.setStopPolicy` is its
   setter — **do not re-plumb it**, and do not make it per-process.
7. `FULL_CONTROL_POLICY` keeps every stop, unchanged.

Done when: `pnpm check` green; a real-Forge test reaches the London mulligan step
and asserts the hand is offered, failing against today's code; `auto.test.ts`
proves the end step is passed by default and stopped when the setting is on,
