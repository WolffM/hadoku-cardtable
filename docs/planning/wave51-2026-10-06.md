## Why

- *"i don't like the 'Ok' button as a confirm for when spells are on the stack. any game action that requires the
  players to do something should land in the decision box not in the control box. can we change the control box
  word to 'Next Phase' so that button is specifically only for that. and any 'Ok' situations are popups decisions
  instead?"*
- *"also can we keep the same 4 buttons in the control box at all times? just grey out the 'Next Phase' and 'End
  Turn' buttons when they are not relevant."*

(`LiveBoard.tsx`, `playOrDraw` / `confirmPrompt`); W16/W18 moved selections (`selectionPopup`); payment has
`PaymentWindow`. What is left on the bar is Forge's button one ("OK" or another label) and button two ("End Turn",
"Cancel", …) for every other input.

- *"why is the stack carousel so much higher than the decision box? thats silly it should be right above the
  decision box."* (the same match, on Smallpox's "Select 1 land(s) to sacrifice" pop-up at mid-right, with the
  stack thumbnail at the very top of the column and the arrow running the height of the board between them;

## Settled — do not re-open

- **The control box always draws the same four buttons, in this order, every frame:**
  1. **`Next Phase`**: `data-testid="live-button-next-phase"`. It presses Forge's button one (`pressButton(match,
     'ok')`). It is **enabled only** while Forge's input is the priority pass (`InputPassPriority`: its second
     button is `End Turn`, PlayBridge's `END_TURN_LABEL`) **and the stack is empty**. Greyed (disabled)
     otherwise. The label is always `Next Phase`, never Forge's word.
  2. **`End Turn`**: `data-testid="live-button-end-turn"`. It presses Forge's button two (`pressButton(match,
     'cancel')`). It is enabled only while Forge's second button is enabled AND labelled `End Turn`; greyed
     otherwise. It keeps R5's `data-highlight`.
  3. **`Full control`** (`live-full-control`) and 4. **`Concede`** (`live-concede`): unchanged.

  `Settings` stays where it is today; it is not a game button. Nothing in the box appears, disappears or changes
  size between frames (`e2e/table-fit.spec.ts` measures that box every frame).
- **Every other enabled bar button is a decision pop-up**, in the same `.live__prompt` slot and `ConfirmPrompt`
  chrome as T4: `data-testid="live-decision"`, with buttons `live-decision-ok` (Forge's label1, its own word, e.g.
  `OK`) and `live-decision-cancel` (Forge's label2, its own word, e.g. `Cancel`), each drawn only where Forge
  enabled it. Its message is Forge's own prompt line through `plainRulesText`. **No text of ours** (operator, twice:
  no explanatory UI prose). This covers at least:
  - priority with spells on the stack (button one is Forge's pass, which lets the top resolve);
  - declare attackers / declare blockers "done";
  - a board targeting or selection input whose only exit is Forge's button (`Cancel` while choosing a target);
  - any other input the lanes find that enables a bar button and is not the coin toss, a T4 confirm, a W16/W18
    selection or payment. **Each one found is named in the closing note with the Forge input it came from.**

  One pop-up at a time; the existing pop-ups keep priority exactly as today.
- **Delete what this replaces:** the bar's `live-button-ok` and `live-button-cancel`, `secondLabel`, and
  `showsSecondButton`. No old testid survives as an alias (memory: waves must delete what they replace).
- No wire change, no bridge change: this is presentation over the same two `pressButton` sends.
- A behaviour lane proves each rule against real Forge (a Playwright script per rule), with evidence in
  `docs/planning/wave51-evidence/<lane>/`.
