# Wave 5 — friends draft together: the room layer, P3 through P6

Protocol: `docs/handoff/w5.md`. One manager, one sub-agent per lane, all
parallel, no shared files. Runs **concurrently with Wave 4** (card art) in a
separate worktree — see "Concurrent wave", which is binding.

This is the wave the project exists for. The draft engine works and is in
production; what it cannot do is let two people draft the same pod.

## Settled — do not re-open in any lane

- **Full P3–P6, as originally designed.** Operator's call. The four proposal
  docs in `docs/requests/` are the specifications; they were written against
  `0.38.109`, revised against `0.38.110`, and **delivered** to watchparty on
  `cardtable-w2-requests`.
- **`@wolffm/rooms-server` is a box of primitives, not a framework.** Verified
  against the published `0.38.111` `.d.ts`, not against their docs: there is
  **no `createRoomServer` factory and no `authenticate` hook** — that claim in
  their §3.7 was one of four in that document that named things which do not
  exist. What ships is `RoomRegistry`, `joinRoom`/`leaveRoom`, `seatParticipant`
  (with reservations), `emitPerRecipient`/`emitToRole`/`broadcastToRoom`,
  `safeEmit`, `collectGC`, `MultiRateLimiter`, and `resync`'s `classifySeq`.
  **The socket wiring is ours.**
- **`ask` / `RoomStore` / snapshot / service-participant are ABSENT upstream.**
  Grepped the published types. P4, P5 and P6 are ours to build, which is exactly
  what D10 assigned us.
- **Identity is already solved and must not be re-invented.** The edge stamps
  `X-Hadoku-Tier` / `X-User-Id`, and `apps/server/src/edge-auth.ts` verifies
  provenance against `EDGE_AUTH_SECRET` and fails closed. Derive `ParticipantId`
  from that. **Never trust a client-supplied identity.**
- **Seats come from `@wolffm/rooms-protocol`**, including `reservationTtlMs` —
  watchparty shipped reservations in answer to our own W3 ask, so a dropped
  drafter keeps their seat rather than costing the pod its game.
- **The friend gate is absolute.** Every `/cardtable` path is friend tier with
  no public carve-out. A socket path is a path.

## §E — P3: the socket server and the room

1. `socket.io` on the existing express app in `apps/server`. It is already a
   loopback tunnel server behind the edge, so the socket inherits the friend
   gate — **do not add a second auth scheme**, and do not put the socket path
   above `requireMinTier`.
2. A `RoomRegistry<DraftApp, DraftClient>` whose `app` holds the engine state
   from `@hadoku/draft`. Join seats the participant with `seatParticipant`;
   leave releases with `hold: true` so a drop does not vacate the seat.
3. **Per-seat emit via `emitPerRecipient`.** This is P3's whole point: build a
   payload per recipient from `viewFor(state, seatOf(room.seats, pid))`. A
   spectator gets `spectatorView`. **Never `broadcastToRoom` a payload
   containing a seat's pack or pool** — that is the leak the engine's type
   design and the hidden-information tests exist to prevent, and it is the one
   mistake in this lane that matters.
4. Stamp `{epoch, seq}` on every envelope so `classifySeq` works client-side.
   The epoch changes when a draft is rebuilt and not otherwise.
5. Rate-limit picks with `MultiRateLimiter`.
6. Done when: two sockets in one room each receive **only their own** seat's
   cards, asserted over whole serialised payloads; an out-of-turn pick is
   rejected as a value; and a disconnect+reconnect within the TTL returns the
   participant to the **same seat** with their pool intact.

## §F — P4: the ask/correlation registry · **CLEAN ROOM**

> fork of any session that has read this repo's Forge analysis.** D12 is
> non-negotiable and watchparty set it. These packages are MIT; Forge is GPL-3.
> MIT→GPL consumption is fine; the reverse is not.

The sub-agent **MAY read**: `docs/requests/P4_ASK_REGISTRY.md`, this section,
and `@wolffm/rooms-protocol`'s published types. **It MUST NOT read** anything
under `forge/`, `docs/FORGE_ANALYSIS.md`, `docs/ARCHITECTURE.md`,
`docs/WASM_AND_PORTING.md`, or `docs/requests/WATCHPARTY_ROOM_MODULE.md` — all
discuss Forge's implementation of this exact mechanism. If the brief seems to be
missing context, **stop and report**; do not go looking.

1. Implement the spec already written in `docs/requests/P4_ASK_REGISTRY.md`:
   monotonic correlation ids; queue rather than fail when no socket is live;
   replay on re-attach; timeout with a declared value; cancellable; cancelled on
   **seat** exit, not socket drop; an unknown correlation id is **dropped and
   counted, never thrown**.
2. Transport-free and socket-free, like the engine. It takes a delivery
   callback.
3. Done when: the tests named in §2 of that doc pass, and the closing note
   states **exactly which files were read**.

## §G — P5 service participant + P6 persistence

1. **P6 first** — it is what makes P5's crash semantics observable. A
   `RoomStore` with snapshot/restore, **in-memory by default** so nothing
   changes for a host that does not opt in. `SeatTable` is already plain
   JSON-safe arrays and records *specifically so this is writable* — their
   `seats.ts` says so. `CoreRoomState`'s `Map`/`Set` fields are the hard part.
2. The requirement is concrete and testable: **a 45-minute cube draft survives a
   server restart and a browser refresh.** Snapshot the engine state and the
   seat table; restore and continue.
3. **P5**: `role: 'service'` with attach / detach / heartbeat / crash→room
   survives / resync on re-attach.
4. Done when: a test snapshots a draft mid-pack, drops everything, restores, and
   the next pick lands on the right seat with the right pool — and the restored
   epoch differs from the original, so a stale client resyncs rather than
   silently applying to a rebuilt draft.

## §H — The wire schema, and the client socket driver

1. **First commit: the envelope in `packages/shared`.** Extend the existing
   `DraftView` with the transport wrapper — event names, join/leave, pick
   action, error shape. The manager lands this before dispatching E.
2. `apps/ui/src/draft/socket.ts`: a driver with the **same surface** as today's
   in-process `live.ts` (`startDraft`, `applyPick`, `isComplete`, `myPool`), so
   `DraftScreen` does not change. That interchangeability was the point of
   building the UI against fixtures first; do not spend it.
3. Use `classifySeq` from `@wolffm/rooms-protocol` on every inbound envelope.
   `gap` → request a resync. `duplicate` → drop, **never** resync (a retransmit
   burst would otherwise become a request storm). `epoch-change` → discard local
   state and refetch.
4. **Keep the local in-process source.** It is how the draft is testable without
   a server and how a regression gets bisected. Add socket as a third source
   beside `live` and `fixtures`.
5. Done when: two browser contexts draft the same pod and see each other's picks
   land; a refresh mid-draft returns to the same seat; and the fixture and local
   sources still work unchanged.
