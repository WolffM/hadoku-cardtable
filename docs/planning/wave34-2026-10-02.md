# Wave 34 — the escape hatch works, and nothing shipped is untested

Protocol: `docs/handoff/w34.md` carries it. **Four lanes, all dispatched at t=0.**
Implementers commit and stop; the manager verifies from artifacts and lands lane by lane,
**in ONE push at the end**.

**Why.** Wave 33 built scripted Forge positions and, with them, found a real bug: **with Full
Control on and an opponent's spell on the stack, clicking your own instant does nothing**
(`docs/planning/wave33-evidence/e-findings.md` §E1). Full Control is the operator's stated escape
hatch for every stop the defaults skip, so it must work. It also found Ponder's follow-up decisions
being answered with no click (§E2). And four things shipped with no test that exercises them: the
order-of-triggers rule (Q8), the Choose X slider, poison counters, and the rail-row fix. This wave
closes all six. **Deck-library integration is NOT here** (the operator has not reviewed the selection).

## Settled — do not re-open in any lane

- Everything w31–w33 settled stands: own spells do not hold priority; the single layout is always two
  tiers; scenarios are probe-gated (`CARDTABLE_PLAY_PROBE=1`) and never in production.
- **A spec that cannot fail is not a spec.** Every new spec asserts its situation occurred first.
  "Unit-tested only" is written as that. A new e2e spec needs **ten consecutive green runs**.
- **Diagnose before fixing** §E1 and §E2. Both evidence files rule things out already; do not re-test
  those.
- **No jar install by a lane.** If §E1 or §E2 needs a Forge change, the lane stops and reports; the
  manager asks the operator (wave 31's pattern: build to `~/.cache/cardtable-w34/`, the operator installs).
- No WotC trademarks, no money, friend gate, no image bytes in the bundle.

## §S — Server play (§E1, §E2, Q8, two scenarios)

1. **§E1 — Full Control blocks your own response.** Repro: `lone-spell.state`, bob casts Memnite, alice
   turns Full Control on, clicks Mana Leak: nothing (no Pay Mana Cost, stack stays 1, a generic
   `getAbilityToPlay` ask surfaces ~15 s later on its own schedule). With Full Control off the same click
   casts. Find where the click is lost (the client's offer, `match.ts`'s act path, the bridge, or
   Forge's `YieldController` with `FULL_CONTROL_POLICY`). Write a real-Forge test that reproduces it
   first, then fix the cause. Evidence `wave34-evidence/s1-full-control.md`. If the cause is in the
   browser half, hand it to G with the evidence.
2. **§E2 — Ponder resolves with no decision.** `ponder.state`: after the cast, no ask reaches the browser
   and the stack empties. Something answers the look-at-three / reorder / shuffle decisions: find what
   (a server auto-answer in `auto.ts`, `match.ts`'s auto path, or Forge's own default), with the asks it
   answered logged. A choice that changes the game state is the player's; only a decision with exactly
   one legal answer may be auto-answered. If the auto-answer is in the browser (`prompts/rules.ts`),
   hand it to G. Evidence `wave34-evidence/s2-ponder.md`.
3. **Q8 — the ordering ask, exercised.** w33 could not reach it: a scenario's phase jump never
   materialises Upkeep triggers. Drive the game to Upkeep instead (a loop that passes until Upkeep and
   reads the stack before answering), with two simultaneous triggers. Real-Forge test: no ordering ask
   without Full Control; one with it. Revert the rule: the first fails.
4. **Two scenarios for G's and B's items:** `choose-x.state` (a spell with X in hand and a known amount
   of mana) and `poison.state` (a seat with poison and energy counters). Add their README rows.

**Done when:** `pnpm check` exits 0; each fix has a real-Forge test that fails reverted and passes
restored (counts); both evidence files exist.
