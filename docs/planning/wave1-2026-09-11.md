# Wave 1 — the repo builds, the WASM question is answered, and watchparty is unblocked

Protocol: `docs/handoff/w1.md` carries it. One manager, one sub-agent per lane,
all parallel, no shared files. Implementers commit and stop; the manager verifies
from artifacts and lands lane by lane. This repo has **no deploy target yet**, so
"landed" is "on main and the gate exits 0" — there is no deployed tree to confirm.

## Settled — do not re-open in any lane

Full reasoning in `docs/DECISIONS.md`. Summarised so no lane re-derives them:

- **D2** Forge is vendored; this repo is GPL-3.0-or-later. `forge/` is
  **gitignored** and holds a stock upstream clone.
- **D3** Draft-first: P1 draft → P2 desktop play → P3 bridge → P4 browser client.
- **D4** No Rust/Bevy port. 392,151 lines, no oracle, wrong ownership model, and
  libGDX already ships desktop+Android+iOS.
- **D6** The Forge UI renders **inside the room's central canvas slot**, as an
  iframe payload, modelled on watchparty's `GameModule.tsx`. We are not
  rebuilding the deck editor in React.
- **D10** Watchparty owns room-module P0–P2 and publishes `0.x` at the end of P2.
  We own P3–P6. **No P3–P6 implementation is possible this wave** — design only.
- **D11** Their API shape is accepted as-is: no default for `TApp`; `readyCheck`
  is not core; a participant holds a **Set** of sockets; `ParticipantId` is
  tiered `fk:`/`dev:`/`eph:`; `ask` is participant-keyed with a valued timeout;
  `SKIP` is a symbol; service is a `role`.
- **D13** No money ever · no public tier · never commit/host/proxy card images ·
  no WotC marks in the UI.
- **D14** Maven installs user-local to `~/.local`. No sudo, no host mutation.

## §A — Workspace toolchain

The repo is 15 tracked files, all markdown. Nothing else can start until `pnpm
install && pnpm check` means something. Mirror hadoku-watchparty's conventions
(pnpm workspaces, `apps/*` + `packages/*`, strict TS, flat eslint config) without
copying its watchparty-specific scripts.

1. Root `package.json`: private, `packageManager` pinned to pnpm 11.5.0, engines
   `node >=24 <25`, scripts `check` / `typecheck` / `lint` / `test` / `build`.
   **`license` field must be `GPL-3.0-or-later`**, not MIT (D2).
2. `pnpm-workspace.yaml` globbing `apps/*` and `packages/*`. Carry over
   watchparty's `minimumReleaseAge: 10080` supply-chain cooldown with
   `@wolffm/*` excluded.
3. `tsconfig.base.json` — strict, `module: nodenext`, no implicit any.
4. Flat `eslint.config.js`, `vitest.config.ts`, `.nvmrc`.
5. `.npmrc` + `.github/workflows/ci.yml` running install → typecheck → lint →
   test. **The registry auth secret must be `HADOKU_NPM_READ_TOKEN`, not
   `GITHUB_TOKEN`** — `GITHUB_TOKEN` is scoped to this repo and cannot fetch
   `@wolffm/*` tarballs, and a warm pnpm store hides the 403 entirely.
6. Done when: from a clean clone, `rm -rf node_modules && pnpm install
   --frozen-lockfile && pnpm check` exits **0**, read directly, not through a
   pipe. Record the exit code in the closing note.

## §B — WASM go/no-go spike (the decisive lane)

D7 is provisional and this lane settles it. If `forge-core` + `forge-game`
compile to WASM GC and run, P4 as a React build is deleted and D6's iframe
payload already exists in `forge-gui-mobile`. If it fails, we learn the failure
mode now instead of after Wave 3.

**Fail fast, in this order. Stop at the first step that fails and report the
failure mode — a "no" delivered early is the successful outcome of this lane.**

1. Install Maven to `~/.local` from the Apache tarball (verified reachable, 200).
   No sudo. Do not touch system packages.
2. Get a stock `mvn install -pl forge-core,forge-game -am -DskipTests` to pass
   against the **untouched** clone at `forge/`. Nothing else is possible until
   this does. Record the wall-clock time.
3. **Do not modify `forge/`.** Sentry stubbing (13 engine call sites incl.
   `GameAction`, `AbilityFactory`) and any TeaVM config go in a **separate
   overlay** under `scripts/spike/` — a patch file or a Maven profile applied at
   spike time. `forge/` stays stock so the eventual fork is clean (D2).
4. TeaVM 0.13+ (WASM GC backend — coroutines landed there, which is what makes
   Forge's blocking game thread viable at all). Target: construct a `Game`,
   resolve one scripted card interaction, print the result. Headless, no UI.
5. Report on each independently, because they fail differently: **classlib
   coverage** (which JDK APIs TeaVM lacks), **the enum-of-class-literals
   reflection pattern** (`ApiType` × 206 — does TeaVM's DCE keep them?),
   **coroutines** (does a blocking wait actually resume?), **artifact size**,
   **cold-start time**.
6. Done when: `docs/spikes/teavm-go-no-go.md` carries a **GO or NO-GO** verdict,
   the exact commands to reproduce, and for a GO, the path to a `.wasm` artifact
   plus the output of the scripted interaction. A NO-GO must name which of the
   five items in (5) failed and quote the error.

## §D — Room module P3 / P5 / P6 proposals

Watchparty asked us to propose these interfaces because we are the only consumer:
*"designing them here against no consumer produces a subsystem that rots
untested."* They ratify the public surface; we bring the requirements.

Their `ROOM_MODULE_RESPONSE.md` already fixes the shape for each — **start from
their signatures and refine, do not invent a competing API.**

1. **P3 per-recipient emit.** Their §3.5: `room.emit.perParticipant(event, fn)`,
   `room.emit.toRole(...)`, `room.emit.all(...)`; `SKIP` is a symbol because
   `null` is a legal payload; every envelope carries `seq` and the client
   detects gaps and requests resync. Specify from **our** requirement: a
   spectator must never receive a payload containing another player's hidden
   zone. Include the test that proves it by grepping whole payloads.
2. **P5 service participant.** Their §3.6: `role: 'service'` with an attachment
   lifecycle the room owns — attach, detach, heartbeat, crash → room survives,
   clients told, resync on re-attach. Specify the crash semantics *we* need: a
   draft in progress must survive the backend vanishing.
3. **P6 persistence.** Their rooms are `const rooms = new Map()` and a deploy
   destroys state. Our requirement is concrete: **a 45-minute cube draft must
   survive a server restart and a browser refresh.** Propose the snapshot /
   restore interface, in-memory by default so nothing changes for watchparty.
4. Each doc: the requirement in our words, the proposed surface, the tests that
   prove it, and what we'd give up if they say no.
5. Done when: three docs exist, each with a **testable** acceptance criterion,
   and none contains watchparty vocabulary (playhead, media, fragment, playlist,
   tierlist, sprite) in a proposed signature.

## §E — P4 ask/correlation registry — CLEAN ROOM

> **This lane has a legal firewall and the manager must dispatch it to a FRESH
> agent — never a fork of a session that has read this repo's Forge analysis.**

These packages are **MIT**; Forge is **GPL-3.0**. MIT→GPL consumption is fine;
the reverse is not. Watchparty made this non-negotiable, and the session that
planned this wave is itself contaminated (D12).

**The sub-agent for this lane MAY read**, and nothing else:

- `docs/requests/ROOM_MODULE_RESPONSE.md` §3.4 (copied into the handoff verbatim)
- `docs/DECISIONS.md` D11 and D12
- this section

**It MUST NOT read**: anything under `forge/`, `docs/FORGE_ANALYSIS.md`,
`docs/ARCHITECTURE.md`, `docs/WASM_AND_PORTING.md`, or
`docs/requests/WATCHPARTY_ROOM_MODULE.md`. All of those discuss Forge's
implementation of this exact mechanism. If the brief seems to be missing context,
**stop and report** — do not go looking for it.

The requirement, stated without reference to any implementation:

> A server-side caller needs to ask one seated participant a question and await
> their answer, while other work continues. Asks must: carry monotonic
> correlation ids; survive the participant's transport dropping and replay on
> re-attach; **queue** rather than fail when no socket is live; time out with a
> declared fallback that carries a value; be cancellable; and be cancelled when
> the participant leaves the **seat**, not when a socket drops. A reply bearing
> an unknown correlation id is **dropped and counted, never thrown**.

1. Write `docs/requests/P4_ASK_REGISTRY.md`: the requirement, the state machine
   (issued → delivered → queued → replied / timed-out / cancelled), the surface,
   and the tests.
2. Tests to specify, at minimum: an ask that times out returns the declared
   value; an ask replayed after reconnect resolves; an ask cancelled by seat-exit
   rejects; an unknown correlation id increments a counter and resolves nothing.
3. Done when: the doc exists, is written **only** from the requirement above, and
   its closing note states explicitly which files were read.
