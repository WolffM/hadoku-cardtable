## Wire contract (D owns the schema; G reads it)

New file `packages/shared/src/room-tables.ts`, exported from
`packages/shared/src/index.ts`. D owns that one export line.

```
RoomView.tables: RoomTable[]                 (always ≥ 1; a room starts with one)
RoomTable = {
  id: string,                                 ("t-" + 8 hex; the first table's id is stable for a room's life)
  players: { memberId: string, name: string }[],   (0–2, in seat order)
  matchId: string | null,                     (the live game's match, or null)
  series: {
    length: 1 | 3,
    wins: [number, number],                   (by seat)
    games: { matchId: string, winner: 0 | 1 | null }[],
    phase: 'seating' | 'playing' | 'sideboarding' | 'done',
  },
}
RoomView.settings gains  matchLength: 'bo1' | 'bo3'   (default 'bo1')
                         sideboarding: boolean        (default false; bo3 reads as true)
RoomView.matchId         unchanged: the FIRST table's live match (every current reader keeps working)
```

Table-scoped routes take the table as an optional `table` body field (or
`?table=` on a GET). When it's absent, the route means `tables[0]`.

- `POST /api/tables/rooms/:roomId/tables` (leader only) adds an empty table and
  answers `RoomTable`.
- `DELETE /api/tables/rooms/:roomId/tables/:tableId` (leader only) removes an
  empty, idle table other than the first.

## §E — Play/draw chooser on a fresh match

Forge tosses a coin only for the first game of its own `Match`. Otherwise the
loser of the last game goes first, and that player is asked
`chooseStartingPlayer` (`forge/forge-game/src/main/java/forge/game/GameAction.java:2364-2416`).
We start every game as a fresh Forge match, so every game is a "first game" and
gets a coin toss. The room needs to name the chooser.

1. **First commit: measure.** A jvm test starts a match with a fixed `seed` and
   records which seat Forge asks, the ask's method on the wire, and the
   `coinToss` the server publishes (`match.ts:213,1055`). The note says how the
   ask reaches the browser today.
2. **`MatchSpec.chooser?: 0 | 1`.**
   - When set, the named seat is the one asked play-or-draw.
   - The published `coinToss.winner` is that seat, so the existing client
     flip/notice stays truthful with no UI change.
   - When absent, behaviour is byte-identical to today.
   - Do it in the bridge. **No change to `forge/` and no new fork pin**; a fork
     change is a jar switch, and memory `prod-jar-switch-is-operators` says that
     switch is the operator's. If the bridge cannot do it, stop and report with
     the measurement.
3. **Done when:**
   - `w71-chooser.jvm.test.ts` passes for chooser 0, chooser 1 and absent, over

## §F — Pairings and standings

The rulings: round 1 is across the table, later rounds pair by score, an odd
player gets a bye, and the AI option is not built. This lane is pure code with
no I/O, so it is unit tests only.

1. `pairRound({ players: { id, podSeat }[], results: MatchResult[], round })`
   returns `{ tables: [id, id][], bye: id | null }`.
   - **Round 1:** players ordered by `podSeat`; player *i* plays player
     *i + ⌈H/2⌉*, and an odd *H* leaves one player unpaired, who gets the bye.
   - **Later rounds:** match points (win 3, draw 1, bye counts as a 2–0 win).
     Pair down from the top, and avoid a repeat pairing while any repeat-free
     pairing exists (backtrack; *H* ≤ 8).
   - **The bye** goes to the lowest-ranked player who has not had one.
2. `standings(players, results)` returns the rows, ranked by match points, then
   opponents' match-win % (33% floor), then game-win %, then opponents'
   game-win %. These are the standard tiebreakers; cite where you take them
   from in the doc comment.
3. `roundsFor(n) = ceil(log2 n)`.
4. **Done when:**
   - `pnpm run check` exits 0;
   - tests cover H = 2…8, odd and even;
   - no repeat pairing over `roundsFor(8)` rounds across 200 seeded random
     result sets;
   - no player gets two byes;
   - reverting the repeat-avoidance fails a test (counts in the note).
