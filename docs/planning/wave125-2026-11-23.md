## Settled — do not re-open in any lane

All by the operator, 2026-11-23, unless marked tracker.

- **A deck is "yours" once touched:** renamed, rebuilt after the draft, favourited, or played
  outside its tournament. Untouched draft decks sink to a "From drafts" section, sorted by last
  played, each tile saying when ("Last played Nov 19" / "Never played · drafted Oct 21").
  Favourites sit above everything.
- **A drafted deck is not yours while its tournament runs.** Its set's art is locked, and no
  rename, delete or art rule applies. Once the tournament ends it is yours, and your art rules apply.
- **Art order:** draft deck still in its tournament → its drafted printing (locked). Otherwise:
  your hand pick for that card → "always use oldest art" (if on) → the default printing.
- **Art rules follow the card's OWNER (tracker, from "should only affect that players cards").**
  Your pins draw your cards, on every screen; your opponent's pins draw theirs. One answer per
  card, the same on both screens and in the replay.
- **Pins are resolved once, at match start**, and written into the match spec, so the recording
  header carries them and a replay draws exactly what the match drew (the operator: "doing it at
  start of game seems pretty clean … during the coinflip"). Resolution runs while the JVM boots and
  never delays a start: a person's document that cannot be read in time means default art
  for that seat, logged once.
- **All new data is self-hosted. Nothing new goes to Cloudflare** (operator, 2026-11-23: "i would
  prefer if all the data was self-hosted so we don't rely on cloudflare for this"). That rules out
  prefs-api (D1) for everything this wave adds.
- **The per-person store (Lane C builds it, first commit): `UserStore`**, owned by the cardtable
  server.
  - One JSON document per person, `<stateDir>/users/<userId>.json`, written temp+rename like
    `draftRooms.ts`, so the nightly `cardtable:state-backup` job already carries it.
  - It sits behind an interface (`get(userId)`, `update(userId, fn)`), so moving it into
    dataplatform's data store later (`docs/planning/telemetry-and-state-inventory.md` §4) changes
    one implementation file.
  - The platform part (the store, its erase hook) lives in `packages/game-server` (MIT, no Magic
    in it). The Magic document shape lives in `games/magic/server/src/users/`.
  - Document shape (Magic):
    `{ favourites: { [deckId]: at }, decks: { [deckId]: { lastPlayedAt } }, built: { [builtId]: { name, format, dck, createdAt, updatedAt } }, art: { oldest: boolean, picks: { [normalisedName]: scryfallId } } }`.
  - The browser reaches it only through cardtable's own `/api/me/*` routes, keyed by
    `httpCaller(req)`. Nobody reads or writes another person's document over HTTP. The server
    reads seated players' documents in-process at match start.
  - **Account erase deletes the document**: a hook beside `packages/game-server/src/erase/recordings.ts`,
    with a test.
- **"Last played" is stamped by our server.** When a match ends, each seat with a `deckId` sets
  `decks[deckId].lastPlayedAt`, bot games included. A one-time backfill, run by the manager after
  the land, reads prefs-api's existing match history and writes the stamps. That is reading our
  data OUT of Cloudflare, which is allowed; the screen never reads Cloudflare.
- **The match history already in prefs-api's D1 stays where it is this wave.** Moving history to a
  self-hosted SQL store is the next programme, with its own wave.
- **New deck uses the existing deck builder** (`deck/DeckEditor.tsx`, the sideboard/build UI),
  improved, not a new editor.
- No explanatory UI text (memory `no-explanatory-ui-text`). State colours are theme tokens.
  Every new control gets a `data-testid`.

## §A — Covers always draw (operator: "many of the decks are missing a cover image")

Measured above: 103 of 174 drafted decks rank a card first whose art the tile cannot credit, so
the tile is blank. The pool data is fine.

1. First commit: a red test from a real snapshot pool, reduced to a fixture. It asserts the
   chosen cover is a creditable art id.
2. The cover rule becomes: the best creditable card → the next creditable card → the deck's
   cube's or set's cover (`coverArtId`, which `decks.ts` sends from the cube meta's own `artId`,
   the one `CubeArt` draws) → the empty band only when there is none.
3. Widen credit coverage so the best card is usually creditable. Either build the artist table
   from the full catalog, or have the server stamp `artist` beside the id. **Measure the UI
   bundle delta** and the lazy chunk's size before and after, and say which mechanism and why.
   No image bytes in the bundle (critical rules).
4. Release note in `docs/releases/pending/`.
5. Done when: the red test is green; the snapshot re-measure prints 0 blank of 174; the bundle
   delta is in the note; `pnpm run check` is green; PPE serves it (`/health` version = the land).
   A is released to C the moment it lands: the manager tells C.

## §B — Art server (released dates, printings, per-player art pins)

1. Catalog: `build-catalog` writes `releasedAt` per printing (Scryfall's `released_at`, already
   in `cards.jsonl`). `catalog.ts` parses it, tolerates its absence, and gains
   `printingsOf(name)` (oldest first, paper, has art, no Alchemy/digital-only) and a search
   index. Regenerate the catalog **into a new file beside the live one** and report its path,
   size and row counts. Swapping it into the live path is the manager's step after the land
   (`catalog.swap()` hot-reloads it, `catalog.ts` header). Say whether that happened.
2. `http/cards.ts`: the two endpoints in the contract, as the first commit. Rate limited per
   caller (`perCallerLimit`) like every costly act.
3. `art-pins.ts`: given the seats (userId, deck, and whether the deck is a drafted deck whose
   tournament is still running), read each seated user's `art` from C's `UserStore`
   (in-process, local disk). Resolve one `scryfallId` per card name per seat by the settled
   order. Report the measured p50/p95 resolve time and the window it runs in (JVM boot → first
   face stamped). It never delays a start: an unreadable document means default art for that
   seat, logged once.
4. `art-ids.ts` honours `seats[i].artPins` for faces seat i OWNS, below the drafted-deck rule
   and above the defaults. Tokens and emblems are out of scope unless trivially owned. The
   recording header carries the pins and a replay draws them: the test builds a match with
   pins, records it, rebuilds the replay and asserts the same ids.
5. Done when: unit tests for resolve order (a pick beats oldest; a tournament-locked draft
   ignores both; an opponent's pins never touch your cards); a jar test (`*.jvm.test.ts`, proved
   on a claw per memory `verify-on-claws-not-hokon`) where seat 0 pins Lightning Bolt to LEA and
   both screens' faces carry LEA's id while seat 1's Bolt keeps its default; the replay test; the
   catalog swap stated; PPE serves it.
