## The shared contracts (pinned here, so no lane waits)

**H's generic host** (`play/host.ts`, platform):

```ts
/** The four lines the host and placement read from any engine; everything else is the game's own. */
export type HostLifecycleLine =
  | { t: 'ready' } | { t: 'fatal'; message: string } | { t: 'frame' } | { t: 'snapshot' };
export interface HostEvents<L extends { t: string }> { onLine(line: L): void; onExit(...): void; queued?(...): void; booting?(...): void }
export interface MatchHost<C> { send(cmd: C): void; stop(...): void; /* … as today */ }
export type MatchHostFactory<L, C> = (matchId: string, spec: MatchSpec, events: HostEvents<L>) => MatchHost<C>;
export interface Durable { epoch: string; owners: (string | null)[]; checkpoint: null } // checkpoint: w105
```

Forge's `BridgeLine`/`BridgeCommand` move, unchanged, to `play/bridge-protocol.ts` (magic). Each Forge importer
names the instantiation: `MatchHost<BridgeCommand>`, `HostEvents<BridgeLine>`.
- Narrowing on a generic `L` with an open `t: string` member does not work in TypeScript (w100's 3.2 finding,
  `~/.cache/cardtable-manager/w100-closing.md` "## 3"). So placement narrows on `HostLifecycleLine` through a type
  guard (`isLifecycle(line)`), never on `L` itself.
- H may refine this shape in its first commit, and tells the manager, who relays it to G.

**G's `GameSession` hooks** (`play/game-adapter.ts`), from w102's coupling list:
- `replayed(cmd)`: a replayed command closes the session's open ask (today `onReplayedCommand`, Forge's
  `reply`/`abort`);
- `ended(reason)`: the session's sweep at stop, fail or exit (today `logFrames`/`closeAllAsks`/
  `tellSeatsItEnded`/`probes`);
- `notice()`: the end-of-server notice (`serverStopping`'s `endNotice`);
- `GameAdapter.classify(line)` returning `'over'` with `{ winners, losers, drawn }`, which replaces `onLine`'s
  `gameover` branch.

## §R — the relay runtime, server half

The relay is a match with no engine. The host relays each seat's messages to the other seats, and to watchers
read-only, through the match's socket. Rooms, seats, rejoin, watchers and the end of the game come from
`MatchShell`. Phase 6's native bomberman is this runtime plus the bundle's `channel`.

1. A `RelaySession implements GameSession`:
   - seat messages are opaque JSON;
   - each one is delivered at most once, in order per sender (the same semantics as w101-S's reference
     `MatchChannel` in `@wolffm/rooms-protocol`; read it);
   - a watcher's send is refused;
   - the game ends when the leader's bundle says so (`{ t: 'over', winners }`), or when every seat leaves.
2. **The socket path:**
   - a new route (in a new plugin file) that upgrades a seat's or watcher's connection to the match's relay;
   - auth reuses the play socket's seal (the kernel's `sealed`/floor), never a new check;
   - per-caller rate limited (`perCallerLimit`, a new `act` name).
3. **Prove it:**
   - unit: two seats and a watcher on real WebSockets against a test server: order, at-most-once, a watcher's send
     refused, a seat's rejoin resuming delivery, the end recorded by the shell;
   - mutation: drop the watcher guard, and the test goes red. Record the counts;
   - `check`. No e2e: there is no client until phase 6.
