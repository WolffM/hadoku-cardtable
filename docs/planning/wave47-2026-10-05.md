## Settled — do not re-open

- **Fast Mode is a setting, and it is OFF by default.** Off means paced. On means today's behaviour, exactly:
  every frame is applied the moment it arrives. It sits in the existing settings panel (`SettingsPanel.tsx`)
  as one plain toggle labelled `Fast Mode`, with no explanatory text.
- **Pacing is a transport wrapper, not a change to the fold.** `startMatch` already takes `options.transport`
  (`match.ts:713`). P writes `live/pace.ts`, a `MatchTransport` that wraps the socket transport and releases
  `MATCH_EVENTS.serverToClient` payloads on a schedule. Every other event and every outgoing frame pass
  straight through. `match.ts` is w46's this wave; P never edits it.
- **The pacing rule:**
  - an event arriving after the table has been quiet is applied at once, so a seat's own action never feels
    laggy;
  - a BURST is spread out: each visible event in it waits its delay after the previous one. That covers the
    AI's turn, a spell resolving, a card leaving the stack, a phase change and a draw;
  - order is never changed and nothing is dropped;
  - toggling Fast Mode on mid-match flushes the queue at once.
- **Delays are data:** one exported table in `pace.ts`, keyed by event class, which the operator will tune
  by feel. Starting values are P's proposal (recorded in evidence), e.g. a stack item resolving ~600 ms, a
  phase change ~250 ms, a draw ~200 ms. Classify from the frame's own content (the delta's `Phase`, zone
  lists, `stack`), never from prompt prose.
- **e2e runs in Fast Mode.**
  - The play harness turns Fast Mode on for every seat, through whatever seam P picks: the prefs server the
    harness already runs locally (`e2e/prefsLocal.ts`), or an init-script global read only as the
    default. P chooses, says why, and keeps it out of the production path's behaviour.
  - The one spec that tests pacing turns it off.
  - Measure forge-e2e wall time before and after. It must not grow by more than 5%.
- No explanatory text anywhere (operator, twice).
- **No version bumps and no ledger edits in the lane.** The manager does not push; it reports ready, and the
  tracker integrates w46 then w47 and pushes once.
