# Wave 18 — the room owns its client: mode toggle at create, containers per streamed room

Protocol: `docs/handoff/w18.md` carries it. One manager, one sub-agent per
lane, all parallel, no shared files.

## §0 — The decision this wave implements (D19 + D19a — settled, do not re-open)

**Operator, 2026-09-22:** *"let's have it be a room toggle. otherwise we have
to side-load host the 1gb streaming clients which is awful. on room create
the room creator can decide the mode."*

Two frontends stand (D19): our React board, and Forge's own UI streamed from
a container. **The choice is the ROOM's** — made once by the creator at room
creation, immutable for the room's life. Not per user, not mid-game.

- A room in `builtin` mode is exactly today's product. It never touches a
  container.
- A room in `streamed` mode provisions its containers when it is created and
  reclaims them when it dies. Its members play through the streams; the
  match runs **inside the containers** on Forge's own networking (host in
  seat 0, join by container name — the flow the static bench proved live).
  Our engine (`apps/server` JVM pool) is not involved in streamed rooms.

**What died with D19a (no lane builds any of it):** the options-menu client
picker, mid-game switching, and client-agnostic seats. A seat is not a
renderer-agnostic identity any more; it is whatever its room says it is.

**Why this wave exists (the operator's parallel-tracks goal):** after w18,
the React tiers (track R: tiers 2–3 of our board) and the outer-shell
adoption (track S: hadoku_site's `templates/game`) touch **disjoint files**
and can run as concurrent waves. w18 is the seam that makes that true.

### The one open operator question (tracker's message, not a lane)

**Container count per streamed room.** This wave's recommendation: **one
container per seat** (a 2-player streamed room = 2 containers ≈ 2.5 GiB,
matching the bench). The alternative — one shared container per room, all
players driving one screen — is cheaper but is not a game. Confirmed with
the wave's dispatch; lanes below assume per-seat.

## Settled — do not re-open in any lane

- **No money, ever. The friend gate stays** on every path this wave adds.
  The stream routes keep both halves gated exactly as `stream/index.ts` does
  today (HTTP below `requireMinTier`; the upgrade half re-applying the floor;
  404, never 403).
- **A streamed room's match is Forge's own.** We add no bridge, no protocol
  code, no fork changes. Our server is the room layer + the pipes.
- **No image bytes in the repo or bundle**; a card's art stays a lookup.
- **Never build in `forge/`**; never initialise the submodule in a worktree;
  never `git submodule deinit`.
- **The static bench at `/cardtable/stream/<n>/` stays up** until the
  operator has played a room-scoped streamed room end to end. It is the
  friend demo's link. Its removal is a later, explicit change.
- **Container hygiene is part of the feature, not polish**: a streamed room
  that dies takes its containers with it; a streamed room everyone left
  stops burning a GiB after a bounded idle window. Numbers the lane pins,
  with a test that proves the reclaim.

## §A — the mode on the wire

**Where rooms actually live:** `apps/server/src/room/lobby.ts` — `Lobby.create`
(:402), `CreateRoomInput` (:103), `RoomView` (:84), `GameType`/`GAME_TYPES`
(:67). `http/rooms.ts` is the HTTP surface (`parseCreate` → `lobby.create`,
:189). `draftRooms.ts` is the draft POD engine and is NOT this; do not touch it.

`CreateRoomInput` and the stored room gain
`clientMode: 'builtin' | 'streamed'`, default `'builtin'`, **accepted only at
create**. `parseCreate` validates it; an unknown value is a 400 with a stated
reason, not a silent default. There is no update path for it — if one is added
later it must refuse, and a test pins that refusal today.

`RoomView` carries it, so `lobby.list()` and `lobby.get()` both expose it and
every client sees what a room is before joining. Rooms already on disk have no
such field: they read back as `'builtin'` (room-store snapshots are read
through `lobby.ts`'s own restore path — pin this with a FIXTURE snapshot, never
a live room file).

**Do not invent a room lifecycle.** Verified while scaffolding: lobby rooms
have no delete, GC, or expiry path today. Reclaim is lane B's problem and B
solves it without a hook from you (see §B). Your lane ends at the field.

Done when: create-with-mode stores and returns it; create-without-mode defaults
to builtin; a bad value is refused with a reason; a pre-existing snapshot
fixture reads back builtin; `list()` and `get()` both carry it; `pnpm check`
green.

## §B — containers the room owns

Today `stream/index.ts` reads `~/.local/share/cardtable/stream/STREAMS` and
proxies `streamBasePort + n`. The static half stays. What B adds is the
**room allocation**:

- A module that, given a room key and seat count, provisions one container
  per seat (`docker run` via `scripts/stream/container.sh` — the script is
  the ONLY thing that talks to docker; the server never shells `docker`
  inline), assigns each a host port, and records the allocation.
- The route learns a room-keyed form — `/stream/<roomKey>/<seat>/` — with
  the same two tier gates the static half has, byte for byte. The static
  `/stream/<n>/` form keeps working (the friend demo).
- Reclaim, **with no seam from lane A** — `index.ts` (yours) already has
  `lobby` in scope at :255 and `draftRooms` at :237, so inject what you need
  there: a `roomExists(id)` closure over `lobby.get`, and (for pods)
  `draftRooms`' registry `onRoomDelete`, which is already wired at
  `draftRooms.ts:229`. A sweep reclaims an allocation whose room no longer
  exists, and on an idle window the lane pins
  (proposal: no websocket attached for 30 minutes → destroy the containers,
  mark the room's streams dead honestly in the view). A streamed room whose
  containers are gone says so; it does not 502 forever behind a live-looking
  link.

**This lane is a HOST-MUTATION lane and says so in its closing note.** The
containers it creates are real; the note reports what ran, what is still up,
and what was torn down. If docker is unreachable in a lane's environment,
the allocation is still fully tested against the script's dry-run mode and
the note says the live mutation did not happen.

Done when: allocation+reclaim are unit-tested against the script (dry-run and
real), the room-keyed route refuses anonymous upgrades with 404 (live-socket
test, like `stream/index.test.ts` today), an abandoned allocation reclaims
on the idle window (test with a fake clock), `pnpm check` green.

## §C — the creator's toggle, and the streamed room's face

**Where the create form actually is:** `apps/ui/src/rooms/RoomList.tsx` — it
already renders the game-type picker off `GAME_TYPES` (:324), and
`rooms/api.ts` holds the wire client (`CreateRequest`, `RoomsClient.create`
:151, `parseRoomView` :68, `RoomView` :28). Both are yours. One form serves
constructed rooms and draft pods alike, so there is ONE place to add this.

That form gains the mode choice, rendered as a plain two-way pick — **our
table** vs **Forge's full client (streams your screen from the server)** — sent
on create and parsed back into `RoomView`. No defaults hidden: the choice is
visible before create, and `parseRoomView` defaults a missing field to
`'builtin'` so an older server cannot render as streamed.

A streamed room's body is per-member stream views — each member's seat gets
its stream (an embedded same-origin frame of the noVNC page; CSP `frame-src
'self'` already allows it). Where the stream is not reachable (CI, containers
absent), the seat shows a stated state — "waiting for the stream" — never a
spinner lie. The room list and room header carry the mode so nobody joins
blind.

No WotC marks in anything this lane draws (the containers' own pixels are
Forge's).

Done when: the create form offers the pick and sends it; a builtin room is
pixel-identical to today (the toggle is the only create-flow change); a
streamed room renders per-seat streams or the honest waiting state; the room
list shows each room's mode; `e2e/room-mode.spec.ts` covers create-builtin,
create-streamed and mode-visible-in-list **without needing containers** (the
stream area asserts the waiting state — CI has no containers and must stay
green); `pnpm check` + `pnpm e2e` green.

## §D — the shell seam (the last seam before parallel tracks)

Track S (the `templates/game` adoption) will replace our hand-written
wrapper. It cannot do that while screens reach outside themselves. D makes
the boundary true and thin:

- `App.tsx` routes; `chrome/` owns everything above the screens; **screens
  import nothing from `chrome/` and nothing global** — anything a screen
  needs (identity, theme state) arrives as props or context from `chrome/`.
- `main.tsx` and `index.html` carry no app logic beyond mount + the
  catalogue token.
- A short doc block in `chrome/AppChrome.tsx` states the contract, so track
  S swaps the wrapper against a written boundary, not archaeology.

Done when: `grep -r "from '../chrome" apps/ui/src/screens/` returns nothing;
`pnpm check` + `pnpm e2e` green with no behavioural change.
