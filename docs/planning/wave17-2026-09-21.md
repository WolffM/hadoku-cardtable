# Wave 17 — our own game UI, tier 1: a game you can actually play

Protocol: `docs/handoff/w17.md` carries it. One manager, one sub-agent per lane,
all parallel, no shared files.

## §0 — The route is decided, and this reverses a standing rule

**Operator, 2026-09-21:** *"let's see if we can build our own UI then. that's
the right route … the forge UI is extremely ugly, and all i ever cared about was
the rules engine anyway."*

**"Do not delete the React board" is REVERSED.** It is not a placeholder
awaiting a Forge-in-a-browser replacement any more. It is the client. Waves
14–16 established why, by measurement:

| route | verdict |
| --- | --- |
| Forge under CheerpJ | ~147 ms, a 1.43 GiB tab, a third-party runtime whose licence forbids self-hosting — and it needs `'unsafe-eval'` plus four host exceptions against hadoku.me's measured CSP |
| streamed Forge | works, but pixels bypass the watchparty netcode, and costs 1.26 GiB + ½ core of hokon per player |
| **our React UI** | local, on our own netcode, inside the site's existing CSP with **no** changes |

### Why this is smaller than it has looked

**The whole client→server surface is 15 methods.** Forge's UI is a thin layer
over the rules: Forge decides what is legal, marks it selectable, and the client
sends back a choice. Playing a land, casting a spell, choosing a target,
declaring an attacker — **one mechanism**. We implement no rules. Ever.

And that mechanism is already on our wire:

```java
// forge-gui/.../IGuiGame.java:272
void setSelectables(Iterable<CardView> cards, int min, int max);
void clearSelectables();
```

**Forge pushes exactly which cards are clickable right now, with a min/max
count.** The product board ignores it.

### The pattern this wave exists to close

`setSelectables` is handled in `apps/ui/src/play/live/jvm-harness.ts` — **the
test harness** — and nowhere in the product. That is the *second* time: the
coin-toss button bar was also handled only by the harness, and every
production match sat at Turn 0 until 2026-09-19.

So **`jvm-harness.ts` is effectively a list of what the product board is
missing.** Lane A diffs it against the product before writing anything.

## Settled — do not re-open in any lane

- **No money, ever.** The friend gate stays.
- **We implement no rules.** If a lane finds itself deciding what is legal, it
  has gone wrong: Forge decides, and the UI renders Forge's answer. A card is
  clickable because Forge said so in `setSelectables`, never because we worked
  out it could be played.
- **The hidden-information rule is absolute.** 144 secrets in Forge's raw
  stream, **0** reaching the seat (`jvm.test.ts`). Nothing in this wave may
  render a card the viewer's seat was not sent.
- **The CSP does not change.** Our UI fits inside hadoku.me's existing policy —
  art from `cdn.hadoku.me` and `cards.scryfall.io` is already allowed. Any lane
  that thinks it needs a CSP change stops and reports.
- **A card's art is a lookup, not a URL** (D15). Use `packages/carddata/src/art`
  — never hardcode an image host in a component.
- **Never build in `forge/`**; never initialise the submodule in a worktree;
  never `git submodule deinit`.

### A and B share an INTERFACE, not a file — and the contract is here

Wave 16's wave file had a bug: lane lists were checked for *overlap* and came
back clean, but a lane was not given a file it *needed*. Overlap and need are
two checks. Here the need is real — A must make B's cards clickable — so it is
settled in advance rather than negotiated mid-wave:

```ts
// B adds these to <Board>. A passes them from LiveBoard.
interface BoardInteraction {
  /** Card ids Forge currently says are selectable (from setSelectables). */
  selectable: ReadonlySet<number>;
  /** Player ids Forge currently says are selectable. */
  selectablePlayers: ReadonlySet<number>;
  /** A card was clicked. Only ever called for an id in `selectable`. */
  onSelectCard(cardId: number): void;
  onSelectPlayer(playerId: number): void;
}
```

B renders a selectable card as clickable and a non-selectable one as inert, and
calls the callbacks. A owns what they do. **Neither decides what is
selectable — Forge does.** B codes against this type with a stub; A codes
against it with a real board; the manager lands B first.

## §A — The interaction layer

1. **Diff `jvm-harness.ts` against the product first.** List every frame the
   harness handles that `live/match.ts` does not, and report the list. That list
   is the most useful artifact this wave produces for the waves after it.
2. Handle `setSelectables` / `clearSelectables` in `LiveMatch`, exactly as the
   button bar was handled (`match.ts`, `prompt`/`buttons`). Carry `min`/`max`.
3. Send `selectCard`, `selectPlayer`, `selectAbility` from the board's
   callbacks. `selectCard` exists today **only in `game-driver.ts`, a test
   driver** — the product has never sent it.
4. **A stale selectable must not be clickable.** When Forge clears or replaces
   the set, a click on the old one must not send — exactly the rule the button
   bar already enforces, for the same reason: a stale click answers the NEXT
   question.
5. Done when: in a real match (`jvm.test.ts`'s shape, against the installed
   jar), a player **plays a land and casts a spell by clicking their own board**
   — not through `hands.ts`. And a test proves a click on a cleared selectable
   sends nothing.

## §B — Cards that look like cards

1. **Card art.** The board has **zero `<img>` tags** today. Render art through
   `packages/carddata/src/art`'s resolver — the same one the draft screen uses —
   so repointing a card stays a one-line manifest edit. Art currently resolves
   to Scryfall for most cards (the CDN upload, O6, has never run); that is fine
   and is not this lane's problem.
2. **Hidden cards stay hidden.** An opponent's hand is a count and a card back,
   never a face. Render only what the seat was sent.
3. **Selectable state**, per the contract above: a clickable card must look
   clickable and an inert one must not. Tapped cards look tapped.
4. **No WotC trademarks** — no card frames, no mana symbols. Art plus our own
   chrome. `{T}` renders as the word TAP.
5. Done when: the board renders both battlefields and the viewer's hand **with
   art**, an opponent's hand shows no faces (a test asserts it from a projected
   frame), and `<Board>` implements the `BoardInteraction` contract with a test.

## §C — A table that never scrolls

The operator, 2026-09-19: *"this module can NEVER require a scroll bar."*

1. The whole match — both battlefields, the hand, the stack, the prompt, the
   button bar — fits a 1280×800 viewport **without a scrollbar**, and a
   1366×768 one.
2. **The button bar must not appear and disappear.** The operator called that
   out as ugly. Give it a fixed home; disable its buttons rather than removing
   it.
3. The match header and invite box were removed on 2026-09-19 (`MatchScreen`).
   Do not bring them back.
4. **Do not mount a second `RoomChrome`.** `App` mounts one; their store and
   socket are module singletons.
5. Done when: a Playwright test at 1280×800 and 1366×768 asserts
   `document.scrollingElement.scrollHeight <= innerHeight` on a live match, and
   the button bar's box is present in every frame of a match rather than
   appearing on demand.

## §D — Tear down the lab, and make CI run the real game

**The lab.** `apps/server/src/lab/**` was a one-day A/B bench and it carries a
proxy in the production server. The route is decided; delete it.

1. Remove `apps/server/src/lab/` and its seven references in `index.ts`.
2. It is inert without its marker file, but **delete the code, not just the
   marker** — a dormant proxy in production is the kind of thing that outlives
   everyone who knew why it was there.
3. Report the host-side teardown for the tracker to run (the containers, the
   docker network, `~/.local/share/cardtable/lab/`). A lane does not run
   `docker rm` against the host.

**CI.** Found in Wave 16: **CI has never run the Forge match e2e.**
`play.spec.ts` self-skips on an unset `CARDTABLE_FORGE_JAR`, and
`.github/workflows/ci.yml` sets none. Green CI has always meant **3 of 4** e2e
tests, and the skipped one is the only test that drives a real child JVM. For a
wave whose whole point is a playable match, that is the test that matters most.

4. Set `CARDTABLE_FORGE_JAR` / `CARDTABLE_FORGE_RES` in CI. The runner is
   self-hosted on hokon, so the installed jar at
   `~/.local/share/cardtable/forge.jar` is reachable.
5. **Prove the test now RUNS rather than skips** — the Playwright summary must
   show 4 passed and **0 skipped**. A skip reads as a pass; that is the whole
   reason this item exists.
6. Done when: `lab/` is gone, `pnpm check` and `pnpm e2e` pass, and a CI run on
   the pushed commit shows the Forge match spec **executed**, with its duration,
   not skipped.

## The gate, for every lane

`pnpm check` is not the gate; CI runs the browser e2e too. **Every lane here
touches the UI or the server, so every lane runs `pnpm e2e` before landing.**

```sh
export CARDTABLE_FORGE_JAR=~/.local/share/cardtable/forge.jar
export CARDTABLE_FORGE_RES=/home/hadoku/repos/hadoku-cardtable/forge/forge-gui/res
pnpm e2e
```

`export` them — `VAR=x cmd1 && cmd2` sets them for `cmd1` only, and a Wave 12
run skipped its test and exited 0 that way. CI runs on THIS host: do not start a
local e2e while a CI run is in flight.
