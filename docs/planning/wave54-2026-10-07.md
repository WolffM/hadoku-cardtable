## Why

From the operator's Playtest 10 (ledger Z1, Z6, Z7, W2 asked again) on UI 0.32.31, two humans:

- **Z6.** *"after declaring attackers there is no visible change (Lightning Angel has vigilance, so nothing
  turns); mark committed attackers, e.g. a red border."* `card.css:600` turns a card for
  `[data-attacking]:not([data-vigilant])` only; a vigilant attacker is drawn exactly as before it attacked.
  `Board.tsx:1919` already writes `data-attacking` from Forge's own `Attacking` (`adapter.ts:940`).
- **W2 (asked twice).** *"hard to tell when i have a card selected because the background for all cards is
  green"* — the London bottom-pick. Forge marks the cards you have picked with `setHighlighted`; the client
  keeps them in `match.highlighted` (`live/match.ts:535`) and `boardInteraction` folds that set into the
  SAME `selectable` set as the offer (`live/match.ts:1156`), so `card.css:523`'s accent ring is the only
  thing either gets. Nothing on the board reads `highlighted` as its own fact (`grep highlighted Board.tsx`
  is empty).
- **Z7 (with L15, W14).** *"blockers cannot be undone; they should work like attackers: an arrow to what
  they block, and a second click undoes it."* Forge's `InputBlock.onCardSelected`
  (`forge-gui/src/main/java/forge/gamemodes/match/input/InputBlock.java:115-160`, read on the pin): a click
  on an attacker makes it the current attacker; a click on a creature already blocking it calls
  `combat.removeBlockAssignment` (`:134-146`, "lblRemoveFromCombat"); a right-click removes the card from
  combat altogether (`:117`). So the undo exists in Forge and only needs offering. Today `blockTargets`
  (`live/match.ts:1597`) offers attackers and legal blockers while `declaringBlockers`, and nothing offers a
  creature that is ALREADY blocking, so the second click has nowhere to land. The wire carries the planned
  assignments every frame: `AttackersWithPlannedBlockers` and `BandsWithPlannedBlockers`
  (`packages/forge-wire/src/tier-c.ts:504-505`, `TrackableProperty.java:237-238`), and `Blocking`
  (`adapter.ts:941`).
- **Z1.** *"deck selection: every deck box the same size, whatever text is in it."* `.deckpick__option`
  (`screens/screens.css:965`) is a flex column with no fixed height; `.deckpick__name` wraps, so a long
  name makes a taller box. Pinned by `screens/constructed.test.ts` (`deck-option`, `.deckpick__name`,
  `.deckpick__mark`); no e2e covers the picker (`grep deck-option e2e/` is empty).

Landing UNDER this wave (not lanes; listed so nobody re-does them): the tracker's branch `piles-and-taps`
(eight commits, landing with `scripts/land.sh` while this wave runs) ships Z2, Z4, Z5's follow-ups, Z8, Z9,
Z11, the pile-release double select, "Resolve?", the band flash, End Turn without the yield pop-up, the
attack-prompt wording, and the `play.spec.ts:659` / `table-fit` reds on main.

## Settled — do not re-open in any lane

- **No explanatory text** on the board, ever (operator, repeatedly; memory `no-explanatory-ui-text`). A
  mark is a drawing. No "click again to unblock".
- **Theme tokens only**, no hardcoded colour. The attacker mark is an outline in the theme's danger/warn
  token (the operator's "e.g. a red border"); non-vigilant attackers keep their quarter turn as well.
- **A picked card looks picked**, not offered: a filled accent or a check glyph on the tile, with the
  offered ring unchanged for the rest. Keyboard and `aria-checked`/`aria-pressed` say the same thing the
  drawing says.
- **Undo a block with the second click, exactly as attackers undo** (Forge's own `InputBlock` behaviour).
  Right-click stays cancel-live (`gestures/install.ts:822`); it does not become Forge's button-3 path.
- **The arrow from a blocker to the attacker it blocks persists while declaring**, drawn from the wire's
  `AttackersWithPlannedBlockers`, never from a click the client remembers; after Forge confirms it draws
  from `AttackersWithBlockers`. Arrow geometry is `aimAt` (`gestures/arrow.ts`), nothing new.
- **Deck boxes:** a fixed box (grid rows of one height), the name clamped to two lines with an ellipsis and
  the full name in `title`; the art, colours and "chosen" mark where they are.
- **Delete what you replace** (memory `waves-must-delete-what-they-replace`): each closing note carries
  `made dead / deleted: <what>, −N lines`. Comments explain code; ticket ids and wave letters go in commit
  messages only.
- Jar and e2e work dirs on disk: `$HOME/.cache/cardtable-play-work/w54-<lane>`. e2e ports **49xxx** for

  short `heavy.lock` flock (≤25 min), never while waiting on anything; a plain `pnpm exec vitest run <path>`

- Landing: `scripts/land.sh` from the wave worktree after each verified lane; CI is the gate; nobody waits
