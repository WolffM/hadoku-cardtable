# Wave 14 — can Forge's own client run in a browser? A spike, not a build.

Protocol: `docs/handoff/w14.md` carries it. One manager, one sub-agent per
lane, all parallel, no shared files.

**Three of the four lanes are SPIKES. They answer a question and change no
product code.** A spike that quietly becomes an implementation has failed at
its job, which is to make a decision cheap.

## Why this wave exists

The operator played a match on 2026-09-19 and could not cast a spell. Their
conclusion, and it is the right one:

> *"why aren't we using the proper forge UI? we shouldn't be trying to
> handroll the game UI at all."*

The blunt fact is that **Forge ships no browser UI** — `forge-gui-desktop`
(Swing), `forge-gui-android`, `forge-gui-ios`, `forge-gui-mobile-dev`
(libGDX), and no HTML/GWT backend anywhere in `forge/pom.xml`. So this is not
a switch anyone can flip.

The operator rejected the two obvious alternatives, for one reason each, and
both reasons are correct:

- **Friends run Forge desktop against our server** — *"lame because it doesn't
  utilize the watchparty netcode at all which was the whole point."* True: if
  Forge's own client drives the match, Forge's netcode carries it and our room
  layer is bypassed.
- **Finish the React board** — *"it will take forever and it's not ever gonna
  happen."*

**Only a browser-side Forge client gives both the real UI and our netcode**,
because it would still speak through our bridge. That is what this wave is
trying to find a route to.

## The thing D7 never asked

`docs/spikes/teavm-go-no-go.md`'s own title is *"can `forge-core` +
`forge-game` run in a browser?"* — **the ENGINE**. It died because
`Game.java:97` constructs a Guava `EventBus`, Guava's `LocalCache$Segment`
extends `ReentrantLock`, and TeaVM 0.15.0 ships zero classes in
`java.util.concurrent.locks`.

**We do not need the engine in a browser.** It runs on hokon, in a real JVM,
today — `docs/FORGE_JAR.md`, one child JVM per match. We need the **client**.

Both of D7's "usual killers" actually passed: coroutines PASS, enum-of-class-
literals reflection PASS. It died on plumbing reached from engine code that a
client may never touch. **Nobody has measured the reachable set from a net-play
client.** That is lane A.

## Settled — do not re-open in any lane

- **No money, ever.** This is also why lane B's licence question has an easy
  answer.
- **The friend gate stays.** `/cardtable/*` is friend-tier at the edge.
- **Never build in the vendored `forge/` tree** (D2). Every build in this wave
  is off-tree, in `~/.cache/`. `forge/` must be byte-identical at the end.
- **Never initialise the `forge` submodule in a worktree**, and never
  `git submodule deinit` anywhere.
- **Do not delete the React board.** It is the only thing that plays today. It
  goes when something replaces it, not before.
- **D18:** image URLs are not host-restricted; image BYTES in the bundle still
  are.
- The toolchain is off `PATH` on purpose: Temurin JDK 21 and Maven 3.9.16 under
  `~/.local/opt`. `which mvn` finds nothing and has misled two sessions.

## §A — TeaVM against the client (re-opens D7)

1. Build an off-tree consumer that compiles **`forge-gui-mobile`'s net-play
   client path** — not `forge-core`/`forge-game` standalone. `forge-gui-mobile`
   declares `forge-core`, `forge-game`, `forge-ai`, `forge-gui` as compile
   deps, but TeaVM does whole-program DCE: what matters is what is **reachable
   from the client's entry point**.
2. libGDX has a browser backend — `gdx-backend-teavm` from the xpenatan project
   D7 already named. Use it rather than hand-rolling one.
3. **The number that decides this wave:** the missing-API list for the CLIENT,
   against D7's **30** for the engine. If `java.util.concurrent.locks` is not
   on it, D7's killer was never on the client's path and this is live again.
4. If it still links against the engine, find out **why** — which class literal,
   which call chain reaches `Game`. "It still fails" is a much weaker result
   than "it fails because `X` reaches `Game.java:97` through `Y`", because the
   second can be worked around and the first cannot.
5. Do **not** try to make it run. Linking is the question; a running game is a
   later wave.
6. Done when: `docs/spikes/client-wasm.md` gives the client's missing-API list
   with counts, next to D7's 30, and says GO or NO-GO with the command that
   reproduces it. A NO-GO names the exact call chain.

## §B — CheerpJ

TeaVM's own docs, quoted in D7 as a headwind, say it is *"not suited for taking
your large existing codebase in Java and producing JavaScript."* That is
precisely CheerpJ's stated purpose: run existing JVM bytecode, full JDK,
**including Swing**, in a browser. If it works it targets
`forge-gui-desktop` essentially unmodified.

1. Establish the **licence** first, in writing, before any engineering. CheerpJ
   is free for non-commercial use; this project's brightest line is "no money,
   ever" (`docs/LICENSING.md`). Confirm it and quote the term. If the licence
   does not fit, stop there and say so — that is a complete and useful answer.
2. Then the hard question, which is **networking, not rendering**: a browser
   cannot open a raw TCP socket, and Forge's client speaks a Netty protocol.
   CheerpJ tunnels sockets over WebSocket. Find out what that actually requires
   on our side and whether our bridge can terminate it. **Do not assume it
   works because the docs say sockets are supported.**
3. Then rendering: does a Swing app of this size run at a usable frame rate?
   Measure something — first paint, a click round-trip — rather than asserting.
4. Done when: `docs/spikes/cheerpj.md` states the licence verdict with the
   quoted term; says whether Forge's client can reach a server from inside it,
   with what shape of proxy; and gives a GO / NO-GO / GO-WITH-COST.

## §C — Streaming, costed honestly

The operator raised this themselves: *"a hosted VM environment that launches
the native desktop app and pipes the window through an iframe."* It is the
fallback, and it has a known flaw — **pixels bypass our netcode exactly as
option A did**, which is the reason the operator rejected that option.

So this lane's job is to make the fallback *decidable*, not to sell it.

1. Cost one match: container image size, RAM, CPU, and what hokon can run
   concurrently. Forge desktop under `Xvfb` is the shape; `x11vnc`/`noVNC` or
   KasmVNC/Selkies are the candidates.
2. Measure latency honestly on this host. A click-to-pixel number, not a claim.
3. State plainly what it gives up: our room layer no longer carries the match,
   only the chat around it.
4. **Do not build it.** A Dockerfile and a measurement is the deliverable.
5. Done when: `docs/spikes/streaming.md` gives per-match resource cost, a
   measured latency figure with how it was taken, the concurrency ceiling on
   hokon, and an honest paragraph on what is lost.

## §D — The hadoku chrome cardtable never got (ships either way)

cardtable was hydrated from `templates/tunnel-loopback-ui`, which scaffolds no
UI, and the hydrator's chrome warning only fires for proxy apps — so nothing
ever handed this app the fleet's front-end conventions
(`docs/requests/HADOKU_SITE_GAME_TEMPLATE.md`). The operator noticed: no theme
selector, and `anon` where their name goes.

**This lane ships whatever the spikes conclude**, because it is the frame
around the game, not the game.

1. `HadokuThemeRoot` + `useHadokuTheme` from `@wolffm/themes`, and `AppHeader`
   from `@wolffm/task-ui-components`. `AppHeader` renders the theme picker and
   the settings gear itself — they are not props.
2. The four CSS imports the templates list. Copy the live reference:
   `hadoku-conjure/packages/ui/src/{App,entry}.tsx`, and
   `templates/tunnel-contained/packages/ui/src/` for the generic version.
3. **Do NOT add a local `useTheme` / `themePrefs` / `themeConfig`.** The
   template file says this in capitals and it is the whole point of using
   theirs.
4. The display name already comes from the fleet's `whoami()`
   (`apps/ui/src/room/RoomShell.tsx`). Do not add a second identity path.
5. **One `RoomChrome` per page still holds.** Their store and socket are module
   singletons. Do not mount a second while moving things around.
6. Done when: the theme picker works and persists across a reload; the header
   shows the viewer's real name; `pnpm check` AND `pnpm e2e` both pass; and no
   local theme hook exists.

## The gate, for every lane

`pnpm check` is typecheck + lint + vitest. **It is not the gate.** CI also runs
the browser e2e, and a UI change that passed `check` went red on `main` on
2026-09-19 for exactly this reason. Any lane touching `apps/ui/**` or `e2e/**`
runs `pnpm e2e` before reporting:

```sh
export CARDTABLE_FORGE_JAR=~/.local/share/cardtable/forge.jar
export CARDTABLE_FORGE_RES=/home/hadoku/repos/hadoku-cardtable/forge/forge-gui/res
pnpm e2e
```

`export` them — `VAR=x cmd1 && cmd2` sets them for `cmd1` only, which made a
Wave 12 run **skip** its test and exit 0.
