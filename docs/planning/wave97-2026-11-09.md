## Settled — do not re-open

- **Room logic is identical across apps; only CSS and UI differ.**
- **Ready is per userId.** The leader moves only on Leave, to the earliest-joined member, never on a disconnect. A
  spectator never takes an active seat. Nobody unseats another. Joining a room means joining its chat.
  (`seats-and-watchers-contract`, plan 739–744.)

  on a real sanitized room file. A quarantined room is a failure.
- Nothing a player sees changes, except bomberman's rooms surviving a restart and its lobby updating live.

## §C — chat served by cardtable; disconnect grace on PresenceTracker

Today `apps/ui/src/room/RoomShell.tsx` mounts watchparty's `RoomChrome` with `serverOrigin={watchpartyOrigin()}`, so
every cardtable room's chat is stored and served by watchparty, and opening a cardtable room holds watchparty's deploys
(w96-B note).

1. Cardtable serves its own rooms' chat with `rooms-server/chat` (`createChatHistoryStore`), behind cardtable's member
   gate and room membership. It speaks the wire `RoomChrome` already speaks; read watchparty's `apps/server/src/ws/chat.ts`
   and the `RoomChrome` source in `@wolffm/watchparty-ui` for it. `RoomShell` points `RoomChrome`'s chat at cardtable's
   own origin. A non-member reads nothing (w96-B's fix).
   - **If `RoomChrome` can't take a separate chat origin without a watchparty-ui change, stop and report:** that's a
     watchparty change for the next step.
2. The disconnect grace in `room/socket.ts` (`:493-509`, `liveConnections :304`, `seatReleaseMs` 30 s) and
   `draftRooms.ts` (`:171,248,264`, `vacateAfterGrace`) run on `PresenceTracker`. Same timings, same
   `releaseAbandonedSeats` call.
3. Done when:
   - a two-browser e2e on the claws: two members chat in a cardtable room, a non-member gets nothing, and the
     messages are served by cardtable's origin (assert the request host);
   - the disconnect specs are unchanged and green;
   - `pnpm run check` exits 0;
   - after PPE: cardtable's chat works on PPE, and watchparty's deploy-busy probe no longer counts cardtable rooms
     (read watchparty's `/api/deploy/busy` with a cardtable room open on PPE).

## §B — bomberman's rooms on the core

   them.
4. Done when:
   - its suites pass, with a test that a room survives a server restart and one that a second client sees a new room
     pushed with no poll (each red against today's code);
   - its CI and deploy are green;
   - live: `/health` ok, a room made, the server restarted (a redeploy), and the room still listed. Say what you
     couldn't verify.
