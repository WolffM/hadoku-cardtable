## Settled — do not re-open

- Replays force every decision from the log; the AI never decides in a replay (2026-10-26).
- **The fault in the w77 rebuild, read from the logs:**
  - The action log records acts SENT at `host.send`. Live, Forge ignores some of them: an OK sent
    while no input waits.
  - Each act goes over Forge's net layer, whose server runs every decoded message on a fresh,
    unsynchronized thread (`PlayBridge.java` `setPhaseDelayOff`'s comment). Acts sent in order can
    be applied in either order.
  - So the log must hold what Forge APPLIED, in applied order, and a rebuild must send one act and
    wait for its application before the next.
- **Room art order** (operator, 2026-10-27):
  1. The room's own art: a draft's set or cube, or a seated constructed deck's art card (already
     built).
  2. The format era's newest set as of the era date ("Legacy 2011" → the newest set released on or
     before 2011-07-15).
  3. The four format pictures already in `apps/ui/src/front/roomArt.ts`.
  Art is always a lookup (`packages/carddata/src/art`, sources `cdn` and `scryfall`), never a URL in
  a component.
- No explanatory UI text and no tooltips (operator, 2026-10-27).

## §A — rebuild from applied acts

1. **The echo.** When Forge's server APPLIES a seat's act to an open input, the bridge emits a new
   line, e.g. `{"t":"applied","seat":n,"seq":k,"act":<the act>,"input":"<input class>"}`.
   - It is emitted in applied order.
   - An act Forge drops is never echoed.
   - **Look first for a bridge-side hook.** The bridge runs Forge's server in the same JVM and
     already reaches server-side state by reflection (`myInput()`, `field(...)`).
   - A fork change is the last resort. If it is unavoidable, stop and report: a fork change needs a
     jar built on a claw and a pin switch, which the manager does.
2. **The recorder** logs an act only when its `applied` line arrives, in that order. Replies and
   aborts keep their `ask` number. Keep the file format versioned: header `v:2`.
3. **The rebuild** (`origin/w77-d`'s `rebuild.ts` + `rebuild.jvm.test.ts`; cherry-pick or port them;
   delete what the echo makes dead, such as position-polling hacks):
   - send one applied act;
   - wait for ITS `applied` echo in the rebuild;
   - only then send the next.
   - A missing echo within the budget is a divergence: logged, and the rebuild fails.
4. **Bring back `replay-determinism.jvm.test.ts`** from `origin/w77-d`, rebuilt on the applied log.
5. **Wire `rebuild`/`canRebuild` into `attachReplays`** in `index.ts`.
6. **Done when:**
   - the `[nightly]` jar tests pass locally ×3 on two deck pairs;
   - one `forge.yml` claw dispatch with `jvm=` naming both tests is green ×2 (`--repeat-each`). The
     claws are where it failed (runs 40471245587 and 40471255011);
   - `/api/replays/:id` serves a rebuilt stream for a match whose public file was deleted.

## §B — room art

1. **Server.** Each room body gets `art: { scryfallId: string } | null`, chosen by
   `room/room-art.ts` in the settled order:
   - **(1)** A draft's set-cube: a card of that set. A cube: a card of the cube. A constructed table's
     deck art card is already chosen in the UI. Keep that, or move it here if that is simpler, but
     keep one place.
   - **(2)** A dated format id (`legacy-2011-07-15`, `modern-…`, a bare Standard `YYYY-MM-DD`): the
     newest set released on or before that date and legal in that family. Pick one card of it,
     deterministically: the set's first rare or mythic by collector number that has art. Use the
     server's card data (the Scryfall cache, `CARDTABLE_SCRYFALL_DIR`; `released_at`, set type).
     Tests use a fixture, never the host catalog (memory: tests never read the host catalog).
   - Compute per set once and cache it; never per request over the whole catalog.
2. **UI.** `roomArt.ts` uses the room's `art` when present, then the four format pictures. It
   resolves through the art lookup with the `scryfall` source when there is no manifest row.
3. **Done when:**
   - unit tests cover era → set → card for Standard, Modern and Legacy dates, a set-cube draft and a
     cube draft;
   - a screenshot of real art rendering on the room cards. The e2e harness blocks image requests, so
     use a private Chromium script against the built UI with the image route allowed.
