## §A — The play surface (items 6, 7, 8, 9, 10, 11-render, 12-backs, 13, 14, 15, 4-avatar)

You own `apps/ui/src/play/` whole because it is one coupled surface: ten test
files pin `Board.tsx` and thirteen pin `adapter.ts`, across `live/`, `prompts/`,
`inspect/` and `gestures/`. That is the reason for the size, not ambition.

**Combat (item 6).** *"creatures should tap when they are attacking. i hate the
'alpha strike' button just delete it. i would prefer the box draw method. theres
a weird 'orange' outline around the ghoul in addition to the blue outline, lets
get rid of the orange one."*

1. An attacking creature draws as TAPPED. Forge's own `tapped` is already on the
   wire and already drawn; an attacker must read the same way.
2. Delete the alpha-strike affordance. The box-draw (marquee) selection already
   exists in `gestures/marquee.ts` and is the operator's preferred way in.
3. Delete `[data-attack-intent='refused']` — the orange dotted outline. Keep the
   `'sent'` intent mark (the dashed accent), which is the one that reads.

**A card's state is drawn, not written (item 15). This is the lane's headline.**
Operator, 2026-09-28: *"+1/+1 looks really ugly, we need a better way to show
that. actually all the shitty text you have written on the card looks ugly, we
need to find a way to handle all of that with effects."*

It is one function. `Board.tsx:889-897` turns every state into a STRING and drops
it on the card:

```
if (entry.tapped) chips.push('tapped');
if (entry.summoningSick) chips.push('summoning sick');
if (entry.attacking) chips.push('attacking');
if (entry.blocking) chips.push('blocking');
if (entry.damage > 0 && boardPT(entry) === null) chips.push(`${entry.damage} damage`);
if (entry.token) chips.push('token');
for (const c of entry.counters) chips.push(`${c.count} ${c.name}`);
```

Seven states as words on a ~70px tile, over real art. **Replace the chips with a
state layer.** Three are conventional and are not open questions:

- **Tapped rotates the card.** Not the word "tapped". This is also item 6's
  "creatures should tap when they are attacking" — the same change, so do them as
  one and the attacking chip goes with it.
- **Damage is red on the P/T badge**, which the code already half does
  (`boardPT`); finish it rather than writing `3 damage` beside it.
- **Counters are a badge with a number**, not `1 +1/+1`. `+1/+1` is the common
  case and deserves the compact form; a named counter falls back to its name.

The rest — summoning sick, blocking, token — are yours to design, and the
constraints are real: a ~70px tile, legible at that size, and distinguishable
from the SELECTION and ATTACK-INTENT outlines the gestures layer already draws,
so a player can tell "Forge is offering this" from "this is sick". Do not invent
a fourth outline colour; prefer a treatment in a different channel (fill, tilt,
desaturation, corner mark) so colour-blind viewers are not told two things in one
hue.

**Art is not the problem and must not be broken.** Card art DOES render in the
deployed app — the CSP allows `https://cards.scryfall.io`, `art-ids.json` covers
these cards (`Celestial Colonnade|WWK`, `Jace, the Mind Sculptor|WWK`,
`Slagstorm|MBS`, `Tragic Slip|DKA` all resolve), and `CardTile` falls back to the
text tile only when an image FAILS. The committed wave-27 screenshot looks
artless because `e2e/play/browser.ts:43` aborts every off-loopback request on
purpose. So every state treatment must read **over art**, not against a flat tile,
and your evidence screenshot has to be taken with art loading or it proves
nothing.

## §B — The stops stop stopping (item 5, and the log's server half)

*"the game auto-stopped on my upkeep because i have tragic slip avaliable and i
could use it on my own minion … it reveals information about whats in my hand …
upkeep stops like this should not happen unless in full control mode. it's
stopping everywhere, super annoying."*

1. **Adopt `ARENA_STOP_POLICY`'s stop behaviour as the default.** The value
   exists; `skipNonStopPhases: 'always'` is what passes a phase outside the stop
   sets whether or not something is castable (`skipsThisTurn`, `auto.ts`). Decide
   and record whether the default becomes `ARENA_STOP_POLICY` wholesale — which
   also adds declare-attackers and declare-blockers stops, and the operator is
   asking for attack control in item 6 — or only its `skipNonStopPhases`. Say
   which and why.
2. `FULL_CONTROL_POLICY` keeps every stop. That is the operator's stated escape:
   *"unless in full control mode."*
3. **Re-aim what moves, do not weaken it.** The three test families the wave-24
   note named are the ones that observe this: `e2e/play.spec.ts` (yours), and
   `apps/ui/src/play/live/*.jvm.test.ts` (**§A's** — report which moved, with the
   failure, so A re-aims them once).
4. **The log's server half (item 11).** `match.ts`'s `say()` pushes to `s.says`
   and sends to THAT SEAT only, which is exactly why the operator sees only their
   own actions. Making the log the GAME's log means the whole table's events
   reaching both seats. Forge has its own log; decide whether to broadcast our
   `say` channel or carry Forge's, **and do not leak hidden information doing
   it** — a log line naming a card only one seat may see is a leak, and the leak
   check in `fixtures/transcript.ts` is the oracle. If the honest answer is that
   this needs a bridge change, say so and ship the safe half.
5. Done when: `pnpm check` green; `auto.test.ts` proves an upkeep with a castable
   instant is passed under the default and stopped under full control, failing
   when reverted with counts **naming the suite**; `auto.jvm.test.ts` passes
   against the real jar; and the note lists every test §A must re-aim.

## §C — The room screen (items 1, 2)

**Item 1.** *"this is ugly, just the symbols is okay. group them by block and make
them bigger."* Today the era row draws each set's glyph with its CODE beside it,
small and cramped. Drop the text, enlarge the glyph, group by block.

Block data is available and is not in our fixtures: Scryfall's set object carries
`block` and `block_code` (verified — `mbs` → block `Scars of Mirrodin`,
`block_code` `som`). Two honest routes, your choice, write down which: add block
to the pool fixtures through their own generator
(`packages/deck/src/library/build-pool-fixture.ts` — that is what writes
`decks/pools/`, as each fixture's `command` field says), or ship a static map,
which is twelve codes and three blocks plus the core sets. A static map is not a
band-aid at this size; an undocumented one is.

**Item 2.** *"the deck chooser dropdown is very ugly, needs a complete redesign.
it should have a partial art that represents the deck and the two colored symbols.
we cannot use a standard dropdown for this."*

- A card-like option per deck: a slice of art, the deck's colour symbols, its
  name. Not a `<select>`.
- The art: a deck has no art of its own, so pick one — its most expensive card,
  or its first non-land — and say which rule you chose. It resolves through the
  existing art path; **`packages/carddata/src/art/` is not yours**, so if the
  resolver cannot answer for a deck, report rather than inventing a second path.
- The colours already exist: wave 26 §D folded them and wave 27 §D serialised
  them to this screen. Use that fold — two screens must not disagree about what
  colour a deck is.
- It must stay keyboard-reachable and it must still say which deck is chosen.
  Replacing a `<select>` with divs loses both unless you put them back.

Done when: `pnpm check` green; `constructed.test.ts` proves the era row draws
glyphs grouped by block with no set code text, and that the chooser renders one
option per legal deck with its colours and is operable by keyboard — each failing
when reverted; and a screenshot in `docs/planning/wave28-evidence/`.
