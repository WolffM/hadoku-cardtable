    pointer events. Whichever stacks on top wins, so a watcher can't reliably
    pick a board. `w71-boards.spec.ts:229` fails on run 39027167776 (job
    117382478578: "watcher-status … intercepts pointer events").

    `matchRoomId`, which is null until `roomOfMatch` resolves (`useMatchRoomId`).
    So the chat chrome mounts after the board's first layout, and the battlefield

  `setFormat` and `setSettings` all refuse (`lobby.ts:1754,1769,1795`).
- **Game results are recorded lazily.** `recordGameResult` runs only from
  `liveMatchId` (`routes.ts:882-896`), which only `/api/tables` routes reach.
  `GET /api/rooms/:id` can show a finished game as live. The strip
  (`MatchScreen.tsx`'s `fetchRoomTables`) reads that route.

  `ConstructedScreen.tsx:1701-1719`.
- **The UI clients don't speak tables.**
  - `apps/ui/src/screens/tables.ts:287-305` takes no table id.
  - Its own `RoomTable` (:164) clashes by name with `@hadoku/shared`'s.
  - `rooms/api.ts` `parseSettings` (:331-341) drops `matchLength`,
    `sideboarding` and `tables`.
- **The editor can't be finished.** `DeckEditor` (`deck/DeckEditor.tsx:107-124`)

  is no "done". Nothing turns a library deck's `[Sideboard]` into the

## Wire contract (P owns the schemas)

New `packages/shared/src/pod.ts`, exported from `packages/shared/src/index.ts`
(P owns that line):

```
RoomView.pod: null | {                          (null for a constructed room)
  phase: 'lobby' | 'drafting' | 'building' | 'rounds' | 'done',
  seats: ({ memberId: string, name: string } | null)[8],   (lobby phase: the 8 pod seats)
  round: number,                                 (0 until rounds start; 1-based after)
  rounds: number,                                (roundsFor(humans))
  results: MatchResult[],                        (@hadoku/draft's shape, byes included)
  standings: StandingsRow[] & { rank: number }[],
  pairings: { tableId: string, players: [memberId, memberId] }[],   (current round)
  bye: memberId | null,                          (current round)
  built: memberId[],                             (drafters whose deck is saved and legal)
}
```

**Routes (P)**

- `POST /api/rooms/:id/pod/sit` `{seat?: 0..7}` and `…/pod/stand`, in the lobby
  phase only.
  - The pod's ready gate counts seated members only. Unseated members are
    spectators and never draft.
  - Bots fill unseated seats at start, as today.
- `POST /api/rooms/:id/pod/rounds`, leader only, from `building`. It is refused
  until every human drafter is in `built`.
  - It starts round 1: makes one table per pairing, seats both players with
    their **saved built deck** (C's `builtDeckOf`), and records the bye.
  - The tables are bo3 with sideboarding, per the ruling.
- The next round starts **by itself** when every table of the current round is
  `done`. After the last round the phase is `done`.
- **Every table route and start works in a draft room once its phase is
  `rounds`.** `wrongGameType` becomes "constructed, or a pod in rounds".

**Series transitions become eager.** A match ending records its game at once,
so every reader of `GET /api/rooms/:id` sees the truth. The hook already exists:
`onGameOver(match)` (`play/match.ts:3497`, passed through `play/socket.ts:522`)
is wired at `apps/server/src/index.ts:481` to `matchStats.gameOver`. P composes
a second listener on that line, and `play/**` is not edited. `liveMatchId`'s
lazy path stays only as the boot sweep.

## Settled — do not re-open in any lane

All from the operator, 2026-10-17, verbatim in `draft-pods-plan.md`:

- Every match is 1v1.
- The pod lobby is up to 8 seats on the seat UI, and spectators hold none.
