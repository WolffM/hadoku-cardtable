## Why

The plan's last fleet step: *"The devkit (claims, landing, run watching, release notes, telemetry watch) gets
parameterized by app id."* Today these scripts name cardtable throughout. They hardcode:
- paths: `~/.local/state/cardtable/claims.tsv`, `~/srv/hadoku-cardtable` and the PPE tree;
- the workflow names `ci.yml` and `forge.yml`;
- `docs/releases/`;
- the service `cardtable`, the telemetry path `/cardtable` and the ports.

A second game repo, made from `templates/game`, should get the same landing and release discipline without forking
the scripts.

## Settled

- **One config file per repo**, `devkit.config.json` at the root. It names:
  - the `appId`;
  - the state dir;
  - the deploy and PPE trees;
  - the CI workflows and the `check` job;
  - the proof workflow, if one exists (cardtable's `forge.yml`; a repo without one skips the proof step);
  - the release-notes dir;
  - the telemetry service and path;
  - the health ports.

  Cardtable's config reproduces today's values exactly.
- **The code lives in `packages/devkit`** (MIT, layer `platform`), as runnable `.ts` and `.sh` files.
  - Cardtable's `scripts/...` entry points that people and crons call stay at their paths. Each becomes a
    one-line exec of the package's file, which is an entry point, not a re-export shim.
  - **The crontab runs `scripts/telemetry/daily.sh` from the PPE tree, so that path must keep working.**
  - Magic- or Forge-only parts stay in cardtable's scripts. Examples: `build-jar.sh`, the forge pin checks in
    `land.sh`, and the jar env in `prove-and-land.sh`. They plug in as hooks the config names, not as `if appId ==`.
- **Don't publish it in this session.** The publish workflow is w118t's. Leave the package `private: true` and note
  "add devkit to the publish list" for the tracker.
- **Behaviour is unchanged for cardtable.** Every existing test keeps passing:
  - `claim.test.ts`;
  - `collect.test.ts` and `build-version.test.ts`;
  - `watch.test.ts`;
  - the land and prove scripts' own checks.

  Their tests move with the code.
- **Update the docs that name the scripts in the same commit:**
  - `AGENTS.md`;
  - `docs/WAVE_WORKTREE.md`;
  - `docs/RELEASE.md`;
  - `docs/lanes/RULES.md`;
  - `.claude/skills/cutrelease/SKILL.md`.

  Where a path is unchanged, leave the doc as it is.
