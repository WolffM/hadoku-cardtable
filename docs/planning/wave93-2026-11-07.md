# Wave 93 — platform phase 2, server track: the service kernel becomes a package

Protocol: `docs/handoff/w93.md` carries it. One manager, one sub-agent per lane (Sonnet), all parallel, no
shared files. Lanes report; the manager verifies from artifacts and lands lane by lane with `scripts/land.sh`
(`scripts/lanes/prove-and-land.sh` where a lane needs a claw proof).

**Why:** this is the server half of phase 2 of the operator's platform plan (2026-11-06; v2's HTML is at
`~/.cache/cardtable-manager/handoff-2026-11-07/platform-plan-v2.html`). The plan says *"A new MIT
packages/service-kernel"* takes:
- edge auth (plus the template's verifiedOf), the phase-1 gate, base path and bundle check, health v1 and the busy
  probe;
- capacity and telemetry (with service, site and surfaces as parameters), the JSON logger, release announce, the boot
  clock and shutdown orchestration;
- request and caller helpers with perCallerLimit, the usage and client-event relays, the state directory and the
  erase registry.

The second game boots on these instead of copying cardtable's `apps/server/src`. Bomberman's copies of edge auth (the
one that shipped without `member`) are what this package replaces in phase 3.

**This wave extracts; it does not restructure the boot.** `index.ts` keeps its shape. `createGameServer({ id, config,
plugins })` with fixed boot phases and an event bus is **w94**, cut once this lands. Every lane here would otherwise
need `index.ts`, which is 1,211 lines and edited by sessions all day.

**Nothing here changes what a player, the edge or the daily telemetry watch sees.**

## Acceptance — no visible change

No operator-reported item is in this wave, so there is no RED-first two-browser spec. Each lane is accepted on these
proofs:
- **Every lane:**

    surface labels, every `perCallerLimit` act name, every log line's `evt`, and every env var name stay
    byte-identical. A unit test pins each literal under `service: 'cardtable'`. `scripts/telemetry/watch.ts` is

## §K1 — Edge auth, the gate, the base path

`edge-auth.ts` (215 lines, 13 importers) reads the edge's sealed headers: tier, user id, account id, display name,
`verifiedOf`. It also holds the ladder (`TIER_ORDER`, `rankOf`) and `assertFloor`. `gate.ts` (w91-C) is the one floor
for HTTP, the two socket.io servers and raw upgrades. `base-path.ts` checks the bundle and the base prefix, and
`http/origin.ts` stamps the origin.

1. `git mv` all four into `packages/service-kernel/src/{auth,http}/`, then parameterize what names cardtable:
   - the env var prefix in `assertFloor`'s message;
   - the default floor;
   - the base prefix;
   - the bundle's index path.

   The template's `verifiedOf` (hadoku_site `templates/game`) and this one must agree. If they differ, the kernel
   takes cardtable's, and the note says how they differ, so phase 3's bomberman swap knows.
2. The old paths become adapters that bind cardtable's values and keep every export and signature. `room/socket.ts`,
   `play/socket.ts` and `stream/index.ts` need no edit.
3. Tests:
   - the kernel's own tests are a superset of the moved ones: the full ladder; a verified `member` promoted to `friend`
     and an unverified one not (`edge-auth.ts:125`); `public` allowed by the kernel and refused by cardtable's adapter;
   - the mutation in Acceptance;
   - one claw proof `only=jvm` (prove-and-land).
4. Done when:
   - `pnpm run check` is green;
   - the grep in Acceptance is empty;
   - the jvm proof is green;
   - the mutation counts are in the note.
