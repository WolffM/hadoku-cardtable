# Wave 9 — a real match, on a real board, answering a real question

Protocol: `docs/handoff/w9.md`. One manager, four sub-agents in parallel, no
shared files. Gate baseline **1,298 tests / exit 0**. "Landed" = on `main`, CI
green, redeploy green.

Everything needed to play now exists in pieces and none of them are connected.
Wave 7 proved a delta stream round-trips; Wave 8 turned it into schemas and
rendered a board from a real game's packets. Both were **fixtures**. This wave
connects them, and answers the one question that has never been tested:

> **Can a human be asked something mid-match and answer it without desyncing?**

`showConfirmDialog` round-tripped through the real `IToClient` seam in Wave 6 —
client replied, server received, 14 ms — so the *seam* works. What has never
happened is that loop running inside a live game with a board on screen. It is
the single biggest unknown left, and the manager's integration check is exactly
it. Everything else in this wave is in service of that moment.

## Settled — do not re-open in any lane

- **The client decides nothing.** Forge computes all legality. A "prompt
  component" is a UI affordance for one of the **15** SERVER→client methods that
  return a value — `showConfirmDialog`, `confirm`, `showOptionDialog`,
  `showInputDialog`, `getChoices`, `chooseSingleEntityForEffect`,
  `chooseEntitiesForEffect`, `getAbilityToPlay`, `assignCombatDamage`,
  `assignGenericAmount`, `order`, `manipulateCardList`, `sideboard`,
  `openZones`, `tempShowZones`. Re-derived from `ProtocolMethod.java`. **Do not
  invent a sixteenth**; if the engine seems to want one, you have found
  something and should report it.
- **The wire contract is done and is not this wave's to change.** Tier A, Tier B,
  Tier C's state arm, and 41 of 58 events are modelled in
  `@hadoku/forge-wire`; 17 events refuse by name. If a lane needs a refused
  event, that is a finding — report it, do not quietly model it.
- **`forge/` is a submodule pinned at `2ad70eb4`** (our fork: DSN stripped,
  `forge server` implemented). **Empty in a fresh worktree** —
  `git submodule update --init --depth 1 forge`. **Never `git submodule deinit`
  in a worktree**: it unregisters `forge` in the deploy tree, which is the main
  checkout. Wave 8's close-out nearly proved this the hard way.
- **Never build in the vendored tree.** `assert_forge_pristine` checks for
  `target/` dirs *and* asks git, because git alone cannot see them.
- Friend gate, D13/D15 art rules, D16/D17: unchanged.

## §A — The match server

1. Start a Forge match behind our existing socket server. `forge server` exists
   now (our fork). Decide, and write down, whether the match runs in-process or
   as a child process — that decision interacts with lane D and should not be
   made silently.
2. **Map our participants to Forge players.** We have `ParticipantId` from the
   edge and seats from `@wolffm/rooms-protocol`; Forge has its own player model.
   The mapping is the join point and is where identity bugs will live.
3. **Per-recipient emit, same as the draft.** A player's hand is hidden
   information; `emitPerRecipient` exists and the draft already proves the
   pattern. **Never `broadcastToRoom` a payload containing a hand.**
4. Drive `IToClient` over the socket: state via Tier C, questions via the 15.
5. Done when: a match starts from an API call, two seats receive per-recipient
   state, and a test asserts over a **whole serialised payload** that one seat's
   hand never appears in the other's.

## §B — The client transport

1. Connect `Board.tsx` to a live match. **Do not change `Board.tsx`** — it
   renders from a payload and that is exactly why it can be connected without
   editing. Add an adapter beside it.
2. **Use `classifySeq`.** `gap` → resync, `duplicate` → drop and never resync,
   `epoch-change` → discard and refetch. The draft client already does this;
   reuse the pattern rather than reinventing it.
3. Render **one** prompt end to end: `showConfirmDialog`. One, done properly,
   beats fifteen half-wired — and it is the one already proven at the seam, so a
   failure here is a wiring bug rather than an unknown.
4. Keep the fixture source working. It is how a rendering regression gets
   bisected without a server.
5. Done when: the board updates from a live delta stream, a `showConfirmDialog`
   renders and its answer reaches the server, and the fixture source still
   renders unchanged.

## §C — The other fourteen prompts, on fixtures

Lane B wires one. This lane builds the rest against captured payloads, so that
when the transport is proven they are ready to connect rather than to write.

1. Capture real instances where possible: `scripts/spike/tierc/` already
   captures from real games, and a prompt with a real payload behind it is worth
   three invented ones.
2. **`assignCombatDamage`, `order` and `sideboard` are the hard three** — a
   damage-distribution widget, drag-to-reorder, and what is effectively a deck
   editor. Budget accordingly and say if one of them is a wave of its own.
3. Every component takes a payload and returns an answer. **No component talks
   to a socket** — that is lane B's seam and keeping it that way is what lets
   these be tested at all.
4. `sideboard` passes two card pools and expects a deck. `@hadoku/deck` models
   exactly that and round-trips `.dck` over all 95 cubes. Use it.
5. Done when: each component renders from a committed fixture and returns a
   well-formed answer under `@hadoku/forge-wire`'s schema; and the closing note
   says which of the 15 are **not** done and why.

## §D — O3: one JVM per match, or one hosting many

Open since Wave 1, deferred twice, and it stops being deferrable the moment two
matches run at once. Wave 6's spike ran one server and one client **in a single
JVM**, so the per-player cost is entirely unmeasured.

1. Measure, do not reason: heap and startup for one match, then N matches in one
   JVM, then N JVMs. Forge loads 33,752 card scripts in ~1.6 s — find out
   whether that cost is per-JVM or amortised.
2. Include the failure mode in the answer: one JVM hosting many means one crash
   takes every match with it. Say what that costs at our scale (a handful of
   friends), because "isolation" is worth less at 4 players than at 400.
3. **Never build in the vendored tree.** `FORGE_DIR` must point at a copy.
4. Done when: `docs/spikes/jvm-per-match.md` carries measured numbers for both
   architectures, a recommendation, and the crash-blast-radius answer.
