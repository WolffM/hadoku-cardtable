## Settled — do not re-open

- **The server decides before the seat sees.** A window the server will answer is never drawn, pace delay
  or not. Hold a `showPromptMessage` until its `updateButtons`; decide once on the pair; forward both or
  neither. A window no decider can read (InputAttack's per-click refreshes, a status line) is never held —
  that is the narrowing w55 found, and the 2 s lag is the test for it.
- **A second prompt never drops the first** (the overwrite-drop bug): a pending pair is flushed as
  forwarded when a newer prompt arrives for the same seat before its buttons do.
- **Every one of the eight suites is proven on a jar before landing**, plus the six unaudited jvm readers
  and the four unaudited e2e specs. A red there is this contract's and is fixed here, never pinned.
- **The bar stays coherent for the seat:** when a window is withheld, the seat's buttons go out disabled
  (as `maybeConfirmChosenCost` does today), so the control box never shows a live OK for a question that
  was never shown.
- Telemetry: the `prompt-forwarded` / `prompt-withheld` events and the frames ring as built; measure the
  ring on one real 20-turn match and put the numbers in the note; no new store, no endpoint.
- Theme tokens only, no explanatory UI text, delete what you replace. Comments explain code; ids go in
  commit messages only.
- Proof on the claws only: `git push origin HEAD:refs/heads/verify/w57` then
  `gh workflow run forge.yml -R WolffM/hadoku-cardtable --ref verify/w57 -f only=jvm -f jvm='<suites>'` and
  `-f only=e2e -f specs='<specs>'`; a full `forge-jvm` run is `-f only=jvm` with no list. Never `--ref main`;
  delete the branch after. A plain `pnpm exec vitest run <path>` needs no jar env. Never `heavy.lock`.
- Landing: `scripts/land.sh` from the worktree; CI is the gate; the closing note is landed in this file; then
  `touch docs/handoff/w57.READY`. Evidence is text under `docs/planning/wave57-evidence/`.
