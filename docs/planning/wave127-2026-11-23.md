## Why — the request, and what the tracker measured

The request (relayed by the operator, 2026-11-23): *"Be able to look into the games that have
been played against the cubes that have been put into the system. Right now you can't see how
popular or favorite your own."* The operator: *"what we actually need here is a sorting/filtering
bar that lets us sort the cube/sets differently. we'll need popularity data and the users
favorites to get piped through"*, and *"we need better data for when games and drafts are
completed."*

Measured by the tracker against prod (`~/srv-data/cardtable`, 2026-11-23):

- **No finished draft is recorded anywhere.** `podDraftDone` (`games/magic/server/src/room/socket.ts:391`)
  only advances the lobby to round 1. There is no draft event, no draft row in game-stats, and no
  telemetry event for a draft's start or end.
- **No finished match names its cube or set.** `matchStart`'s `attrs.pool`
  (`games/magic/server/src/http/routes.ts:2497`) is a format id, or the draft's id for a draft
  match. The cube is gone by the time the report is built.
- **The draft files keep enough to backfill.** 25 files in `drafts/`: 22 `complete`, 3 `drafting`.
  A cube imported from Cube Cobra keeps its id in every card id (`cc-2plnt-398#0:0:11`: 2 drafts
  of Powered Vintage Cube). Shortlist and set drafts carry card names only, so their source has
  to be matched against the cube and set lists by name overlap. That is the backfill's real work.
- **Uploaded cubes do show.** Prod has 2 imports, both load (no `import-load-failed`), and the
  room picker lists them first (`PoolPicker.tsx:273`). PPE's `cubes/` is empty, so PPE shows the
  8 shortlist cubes only. Nothing to fix there; not a lane.
- **game-stats can already group by an attr.** `@wolffm/prefs-client/games`'s
  `breakdown(attr, { player: '*' })` totals outcomes per value of a match attr. A `cube` attr
  on every match report is therefore enough for "most played"; no new stats endpoint.
- **Favourites today are decks only** (w125: `MagicUserDoc.favourites: { [deckId]: at }`).

## Contracts every lane codes against

```ts
// A — games/magic/server/src/history/drafts.ts
type DraftSource =
  | { kind: 'cube'; cubeId: string; name: string; origin: 'shortlist' | 'cubecobra' | 'list' }
  | { kind: 'set'; code: string; style: 'realistic' | 'set-cube' };
interface DraftRecord {
  v: 1;
  draftId: string; roomId: string; pod: number | null; eventId: string | null;
  rounds: DraftSource[];                 // one per pack round; a Cube/Set room repeats one source three times
  seats: { kind: 'user' | 'bot'; userId: string | null; displayName: string; picks: number }[];
  startedAt: number; endedAt: number; durationMs: number;
  outcome: 'complete' | 'abandoned';
  backfilled?: true;
}
interface DraftRecordStore {
  append(r: DraftRecord): Promise<void>;
  /** `cube:<id>` | `set:<code>` → drafts COMPLETED from it (a round counts its source once per draft) and the latest endedAt. */
  countBySource(): ReadonlyMap<string, { drafts: number; lastAt: number }>;
  anonymise(userIds: ReadonlySet<string>): Promise<number>;
}

// B — added to MatchStart.attrs (string attrs; absent when unknown)
//   source: 'cube' | 'set' | 'custom' | 'constructed'
//   cube:   cubeId   (a Cube room, or a Custom room whose rounds are all one cube)
//   set:    set code (likewise)
//   draftId, event:  the draft and the event the match came from, when it came from one

// C — packages/shared/src/pool.ts
const PoolUsageSchema = z.strictObject({ drafts: z.number().int(), matches: z.number().int(), lastPlayedAt: z.number().nullable() });
// CubeSummary.usage?: PoolUsage; SetSummary.usage?: PoolUsage
// poolKey = `cube:<cubeId>` | `set:<code>`
// GET /api/me/library → { favourites, decks, built, poolFavourites: { [poolKey]: at } }
// PUT /api/me/pool-favourites/:poolKey { on: boolean } → 200 { poolFavourites }

// D — games/magic/ui/src/draft/poolSort.ts
type PoolSort = 'favourites' | 'drafted' | 'played' | 'newest' | 'name';
function sortPools<T extends { name: string; usage?: PoolUsage }>(items: readonly T[], key: (t: T) => string, opts: { sort: PoolSort; query: string; favourites: ReadonlySet<string> }): T[];
```

## §A — the draft record

Nothing records a finished draft today (measured above), so nothing can count one.

1. First commit: `drafts.test.ts`, red on the base. A fixture 8-seat draft run to `complete`
   through the real draft engine appends one record whose `rounds` name its cube, whose seats
   count 15×3 picks each, and whose `durationMs` is `endedAt − startedAt`.
2. The store: an append-only JSONL under `<stateDir>/history/`, written with an fsync'd append
   (one line per draft, never rewritten except by `anonymise`, atomically). It is read once at boot
   into the counts. The erase hook anonymises a deleted account's seats (`userId: null`,
   `displayName` → the erase target's name), with a test.
3. Record at `podDraftDone`, and record `abandoned` when a room still `drafting` is closed or
   swept. Read the room's sources from its round sources, never from the cards.
4. The backfill CLI dry-runs by default and prints one line per draft file: its source, how it
   was decided (`roundSources`, the card-id prefix, or name overlap ≥ 90% with exactly one cube
   or set list), or `undecided` and why. `--write` appends `backfilled: true` records, skipping
   any `draftId` already in the store. **The tracker shows the operator the dry run before
   `--write` on prod.**
5. Done when: the test from step 1 is green and fails with the `podDraftDone` call removed (the
   note says so, with counts). The note pastes the line a claw's real 8-seat bot draft wrote,
   and the dry run's table over `docs/handoff/snapshot/drafts/`: decided N of 22, undecided M,
   each undecided with its reason.

## §B — the match report's source

A match from a draft records the draft's id as its `pool`, and nothing about the cube (`routes.ts:~2521`).

1. First commit: a `stats.test.ts` case, red on the base. A draft room on cube X starts a match,
   and the built report's attrs carry `source: 'cube'`, `cube: X` and `draftId`.
2. `sourceOf(room)` reads the room's pool source (after `f0a3ba514`, the room's settings) and
   answers the attrs. A Custom room whose rounds mix sources gets `source: 'custom'` and no
   `cube`/`set`. A constructed room gets `source: 'constructed'`.
3. A tournament match also carries `event`. Check that `STAT_LIMITS` holds for every new string
   (clip like `report.ts` does).
4. Done when: the test is green and fails with `sourceOf` returning `{}`. The note pastes the
   attrs of a real-Forge draft match on a claw (a spec that already plays one; grep `e2e/` for a
   draft-to-match spec, never a new Forge scenario) read back from the report the server built.
