### Survival of the Fittest — ban-date discrepancy with the brief

The §L brief says to build a fixture for "Survival before and after **2010-10-01**, refused
after it." Forge's own dated files do not put the transition there. I checked every Legacy
archive file in the window by hand:

- `2010-07-16.txt`, `2010-08-27.txt`, `2010-09-03.txt`, `2010-10-01.txt`, `2010-11-08.txt`,
  `2010-11-19.txt` — **not banned** in any of these.
- `2011-01-01.txt` onward (`2011-01-10`, `2011-02-04`, `2011-04-01`, `2011-05-13`, `2011-05-14`,
  `2011-06-17`, `2011-07-15`) — **banned** in every one.

So in Forge's archive, the ban takes effect somewhere between `2010-11-19` and `2011-01-01` —
there is no finer-grained file between those two to pin it closer. Per the Settled rule
("Bans changed often. Check each era's banned list against the dated file, never against
today's"), I'm treating Forge's dated files as authoritative over the brief's assumed date. That
transition point conveniently brackets my own 2010 and 2011 era snapshots (`2010-07-16`, not
banned; `2011-07-15`, banned), so the required "before/after" fixture uses those two files
directly rather than inventing a separate 2010-10-01 pair — see `fixtures/` below.

**T independently confirmed the same thing** in `T-step1.done`, from the TypeScript side
(`legacyFormatAt('2010-10-01').banned` excludes it, `legacyFormatAt('2011-01-01').banned`
includes it), and told M/L to use `2011-01-01` as "after" and the era's own `2010-07-16` snapshot
as "before". That is exactly the fixture built below — no change needed on my side.

### The 2006 swap: a real deck dropped, not replaced (no alternate existed)

`validate-library.ts` flagged `decks/legacy-2006/1-noah-long-landstill.dck` (Noah Long,
Landstill, mtgtop8 deck 265151) with `[over-the-copy-limit] plays 8x Brainstorm, but Legacy (CSP)
allows 4`. Checked the raw cached export (`/tmp/deck-export-cache/265151.dec`): mtgtop8's own
`.dec` export for this deck literally reads `8 [IA] Brainstorm`, and the maindeck totals 62 cards.
This is a defect in mtgtop8's stored decklist (not a Forge transcription failure, and not a
fixable card-name/set typo), so it isn't something this pipeline can correct without inventing a
decklist. 2006's candidate pool was exactly 8 legal, non-duplicate decks and all 8 were originally
`chosen`, so there was **no alternate to promote** — unlike wave 34's three precedent swaps (each
had a next-best alternate to promote into `chosen`), this one has nowhere to go. Dropped it: moved
the entry from `chosen` to `alternates` in `selections/selection-legacy-2006.json` with a
`swapped_out_reason` field (following wave 34's own convention exactly, confirmed by grep — see
`decks/README.md`'s "Three decks the selection chose could not be transcribed" and lane M's
analogous `selection-modern-2013.json` entry for an unrelated untranscribable mtgtop8 export found
the same wave), deleted the `.dck` file, and re-ran `report.py --format LE` so
`review/legacy-2006.md`'s generated table reflects 7 chosen decks. Added a prose note to that
review doc (outside the generated table, since `report.py`'s alternates table has no column for
`swapped_out_reason` and I don't own `report.py` to add one) explaining the drop. **2006 is a
7-deck era.**

### Style-heuristic overrides (`style-overrides-legacy.json`)

Legacy's real archetypes are nothing like Standard's — several of its best-known decks win via a
combo that the card-count heuristic (`analyze.classify`: counterspell/sweeper/draw counts,
creature count, average CMC) reads as creature combat or control, because the heuristic was tuned
against Standard's aggro/midrange/control shapes and has no notion of "this deck's real win
condition is a mill/damage/reanimation combo that happens to run few creatures and some
countermagic as protection." Checked every chosen deck's full decklist (not just the label) before
overriding each one — these are not guesses:

| archetype label | heuristic said | override | why |
| --- | --- | --- | --- |
| Belcher | midrange (default) | combo | pure Goblin Charbelcher ritual-storm (Lion's Eye Diamond, Rite of Flame, Seething Song, Empty the Warrens) |
| TES | control (cards, low creature/high counter reading) or midrange (default) | combo | The Epic Storm — Infernal Tutor/Burning Wish/Ad Nauseam/Tendrils of Agony ritual-storm, identical shell to Belcher/ANT |
| ANT | control (cards) or midrange (default) | combo | Ad Nauseam Tendrils — the same storm shell as TES, inconsistently classified control/midrange across years before the override, which is itself evidence the heuristic has no real grip on this archetype |
| Aluren | midrange (default) | combo | the Aluren + Cavern Harpy + Imperial Recruiter infinite-combo engine |
| Cephalid Breakfast | aggro (cards: 17 creatures, low avg CMC) | combo | self-mill combo (Cephalid Illusionist + Nomads en-Kor engine into Dread Return/Sutured Ghoul) — its "creatures" are mana/engine pieces, not an attacking clock |
| Show & Tell | control (cards) | combo | Show and Tell → Blightsteel Colossus/Emrakul, protected by countermagic — the countermagic is protection for the combo, not a control plan |
| Sneak Show | control (cards) | combo | Sneak Attack/Show and Tell → Emrakul/Griselbrand, same reasoning as Show & Tell |
| Sneak Attack | control (cards) | combo | the same Sneak/Show reanimator-combo shell under a different label |
| Painter / Imperial Painter | aggro (cards: 18-19 "creatures", low avg CMC) | combo | Painter's Servant + Grindstone mills the opponent's deck in one activation; the "creatures" are mana dorks/utility 1-drops (Simian Spirit Guide, Phyrexian Revoker), not a beatdown plan |
| Spiral Tide | control (cards: 0-2 creatures, counterspells) | combo | High Tide + Time Spiral + Turnabout ritual-storm (Brain Freeze/Blue Sun's Zenith as the kill), not a draw-go control deck |
| Next Level Blue | midrange (default — 12 "creatures" cleared the control floor) | control | Gabriel Nassif's Counterbalance-Top control shell (Force of Will, Swords to Plowshares, Vedalken Shackles); its Tarmogoyf/Dark Confidant are proactive removal-backed control pieces, not an aggro/midrange clock, and the only reason it missed "control (cards)" is that Tarmogoyf/Dark Confidant/Trygon Predator/Sower of Temptation all count as creatures against the `cr <= 10` control threshold |

Applying the overrides and **re-running** `select_decks.py --format LE` (not just relabeling after
the fact — the style floor/cap search in `select_decks.py` depends on correct style tags to decide
*which* decks get chosen, so a relabel-only fix would have left the wrong deck list in place)
visibly rebalanced several eras toward combo being properly represented (e.g. 2015 chosen styles
went from `{midrange:4, aggro:4, combo:0, control:4}` to `{midrange:4, aggro:4, combo:4,
control:0}` — once Painter/Sneak Show/Storm were correctly read as combo instead of
aggro/control, the search's combo floor pulled in a real combo deck and dropped the control slot
the pool never actually had enough strength to support). `select_decks.py`'s own printed style_why
field is `override` for every one of these changed picks, so the provenance survives in the
selection JSON (`selections/selection-legacy-*.json`), not just this doc.

Deliberately **not** overridden despite being borderline: RecSur/Survival (2006/2007, Survival-
of-the-Fittest creature toolboxes — aggro-by-cards is defensible since they attack with creatures
rather than winning via an alternate condition), GAT (2006, Gro-A-Tog tempo deck — control-by-
cards is defensible given 8 pieces of countermagic), MUD/Stoneblade/Team America/Elves/Lands
(recurring archetypes with a genuinely mixed real-world classification where the heuristic's
answer isn't clearly wrong). Overriding every borderline call would be re-judging the whole format
by hand rather than fixing clear heuristic blind spots.

### A bug found in `build-library.ts` (owned by lane T, reported, since fixed)

First transcription pass (`--family=legacy --only=<year>`) wrote every era's `.dck` files to the
**repo root** (`./legacy-2016/...`) instead of `decks/legacy-2016/...` — `buildJobs`'s standalone-
mode fallback used `` `${family}-${year}` `` for `directory` with no `decks/`/`DECKS_ROOT` prefix,
and `DECKS_ROOT` wasn't even imported in that file. Also found: every transcribed deck's `Source
URL`/citation hardcoded `&f=ST` regardless of family, which is wrong for a Legacy (or Modern)
citation even though the event/deck ids still resolve correctly regardless of that query param.
Since I don't own `packages/deck/src/library/build-library.ts`, I did not edit it — I moved the 12
misplaced directories into `decks/legacy-*/` myself (a path I do own) and flagged both bugs. The
manager relayed that lane T fixed `build-library.ts` directly (directory prefix + `f=LE`) and had
already re-run it over `decks/legacy-2005/`. I re-ran the fixed script over **all twelve** Legacy
eras afterward (idempotent — reads from the same on-disk `.dec` cache, no new network calls) to
pick up the fix everywhere, then re-ran `validate-library.ts` on every directory again. Confirmed
clean: `grep -l 'f=ST' decks/legacy-*/*.dck` now prints nothing (0 of 131 files); all 131 cite
`f=LE`.

## Deliberately-illegal fixtures (NOT library decks — scratch only, never under `decks/`)

Two checks, each run twice: once directly against the shared Python tools' `analyze.legality()`
(the same function `select_decks.py` uses to decide real-deck legality, against the real card
corpus) in `fixtures/build_fixtures.py` / `fixtures/output.txt`, and once against the full
TypeScript pipeline (`validate-library.ts --family=legacy --dir=<fixture dir>`, real corpus) in

a real chosen deck (`decks/legacy-2010/5-frizork-ant.dck`) with one card line swapped for the
banned test card — not a hand-invented decklist, and kept only in scratch/evidence, never in
`decks/`.

- **Mishra's Workshop, Legacy 2010-07-16 (M11 era): REFUSED** both ways —
  `analyze.legality` → `["Mishra's Workshop (banned)"]`; `validate-library.ts` →
  `[banned] plays 2x Mishra's Workshop, which Legacy (M11) bans`. Banned in every one of the
  twelve eras' snapshot files (2005–2016), so this refusal holds throughout the whole range, not
  just 2010.
- **Survival of the Fittest, Legacy 2010-07-16 (before the ban): LEGAL** both ways —
  `analyze.legality` → no issues; `validate-library.ts` → `OK — legal in Legacy (M11)`.
- **Survival of the Fittest, Legacy 2011-01-01 (after the ban): REFUSED** both ways —
  `analyze.legality` → `["Survival of the Fittest (banned)"]`; `validate-library.ts` →
  `[banned] plays 2x Survival of the Fittest, which Legacy (2011-01-01) bans`.
