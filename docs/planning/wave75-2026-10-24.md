(`m-5c5661529ad9`, e.g. 04:36:12.968), and Forge asked each as an `InputConfirm` with colour names as

answers far left and far right (`const pair = answers.length === 2`, :387; CSS `prompts.css:993-1013`), so a
colour pick looks like a yes/no.

   together, and that a real yes/no still splits (no left, yes right, as AF289 asked).
2. Decide yes/no from what Forge says, not from the count: find how a yes/no confirm differs on the wire

   One rule for every `AnswerRow` caller.
3. Done when: the test passes and fails with the old rule; `table-fit.spec.ts`'s `AnswerRow` block and
   `w70-nissa.spec.ts` agree with the new rule; the ledger row says which confirms changed (count them in
   the bridge's labelled-confirm sites).

## §E — whose turn, whose decision, which phase (items 3, 4, 7)

Three repeats: AF42 asked for an ambient effect on the active player's board on 2026-10-14 and landed;
AF35/AF60/AF113 made priority a 6px ring and a sound; AF14 grows your creatures while you declare. A new
player still could not tell whose turn it was, did not notice decisions landing on them, and pressed End
Turn during their own declare-attackers step three times (05:10:44.651, 05:15:22.466, 05:18:21.444,
`m-5c5661529ad9`). Nothing marks combat for the defender, or for the board as a whole.

Current owners: edge light + spotlight `board.css:495-541` (driven by `data-active`); `TurnCue.tsx`
(mounted `LiveBoard.tsx:2947`, `:3564`); `PhaseRail` `LiveBoard.tsx:1430`; priority ring `card.css:1491-1509`
on `data-priority`; `priority-cue.ts` (used `LiveBoard.tsx:2766-2776`); combat growth `card.css:1069-1118`
on `data-combat-ready`.

1. **Whose turn:** make the active side unmistakable at a glance across the whole board (the play area's
   ambient light and the phase rail together), not a thin edge. Strengthen the existing edge light and
   spotlight; don't stack a second effect beside them.
2. **Whose decision:** when a decision lands on this seat (priority returns with something to do, or any
   ask opens), a short, clear screen-level flash (the board's frame, once, then a steady state while the
   decision is open). It doesn't fire for auto-passed windows. Tie it to the same signal as the sound, so
   the two can't disagree.
3. **Which phase:** combat is visible to both seats. Entering beginning-of-combat or declare-attackers
   marks the board for both players, the attacker's "declare" state reads as "choose attackers" without
   text, and declare-blockers does the same for the defender. The End Turn button during your own
   declare-attackers step must not look like the obvious next press.
4. RED first, per cue: an e2e (or component test) that asserts the cue's state at the moment it must
   show and its absence when it must not (the opponent's turn, an auto-passed window).
5. Done when: each cue's test fails on the base and passes; every e2e spec in the blast-radius row is
   green locally (`— SKIPPED:` grepped); the closing note lists for the operator the PPE moments to look
   at (your turn / theirs; a decision landing on you; both seats at declare attackers and at blockers),
   with the commit on PPE.
