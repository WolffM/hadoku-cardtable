## Contracts between lanes

**1. The recording on disk (C writes; B and D read).** It lives in `CARDTABLE_RECORDINGS_DIR`,
default `~/.local/share/cardtable/recordings` (tests use a temp dir). Per match:

- **`<matchId>.actions.jsonl.gz`** — the action log, kept 90 days.
  - Line 1 is `{"t":"header","v":1,"matchId","roomId","pin","bridge","server","startedAt","spec"}`.
    - `pin` is the Forge submodule sha.
    - `bridge` is the sha-256 of `PlayBridge.java`'s text.
    - `spec` is the `MatchSpec` sent to the JVM, `seed` always set: C assigns one when play did not.
  - Then `{"t":"cmd","seat":n|null,"board":"<sha256>","prompt":"<text>","cmd":<BridgeCommand>}`, one
    per command sent to Forge. `board` and `prompt` are that seat's position: `position.ts`'s
    `boardDigest` and `lastPrompt`, over that seat's raw lines so far.
  - Last, `{"t":"end","endedAt","reason"}`.
- **`<matchId>.public.jsonl.gz`** — the public stream, kept 7 days.
  - Line 1 is
    `{"t":"header","v":1,"matchId","roomId","players":[name,name],"ai":[bool,bool],"decks":[…],"startedAt"}`.
  - Then `{"t":"env","at":<ms since start>,"env":<ServerEnvelope>}` for every envelope the watcher
    channel emitted. These are already projected, so they hold no hidden information.
  - Last, `{"t":"end","endedAt","winner":0|1|null}`.
- **`apps/server/src/play/recording/position.ts`** (C) exports `boardDigest(lines, seat)` and
  `lastPrompt(lines, seat)`. These are the helpers `replay-determinism.jvm.test.ts` proved: fold,
  drop default-valued properties, sort, hash. C moves them out of that test and the test imports
  them.

**2. HTTP (C serves; B reads).** Friend-tier like every `/api` route.
- `GET /api/replays?limit=20` → `{"replays":[{matchId,roomId,players,decks,startedAt,endedAt,winner,source}]}`,
  newest first.
  - `source` is `"stream"` when the public stream is on disk, `"rebuild"` when only the action log
    is and it can be rebuilt (D's `canRebuild`), and `"none"` otherwise.
  - Testing rooms are excluded for non-admins.
- `GET /api/replays/:matchId` → `{"header","envs":[{at,env}],"end"}`.
  - When the stream is gone and `source` is `"rebuild"`, C's route awaits D's
    `rebuild(matchId)`, then serves its result.
  - 404 when neither is possible.

## §C — recorder

1. **Wrap the host factory** in `index.ts` (`attachPlay({ host })`):
   - Give every spec without a `seed` a random one.
   - Record every `BridgeLine` and every `BridgeCommand` into the action log, with each command's
     position.
   - Move `boardDigest` and `lastPrompt` out of `replay-determinism.jvm.test.ts` into
     `recording/position.ts`, and make the test import them. Keep the fold incremental per seat,
     not from scratch per command (a long game has thousands of lines).
2. **Record the public stream** off the registry's `emit` for `WATCHER_SEAT`. Gzip both files at the
   end of the match.
   - Retention: public 7 days, actions 90 days, swept hourly.
   - A 2 GB cap on the directory, oldest public streams going first.
3. **Serve contract 2** from `apps/server/src/http/replays.ts`.
   - `rebuild` and `canRebuild` are injected deps; absent means `source` is `"stream"` or `"none"`.
   - The header and end lines carry what the list needs, so the list never reads a whole stream.
4. Done when:
   - Unit tests cover the writer (header, positions, end, gzip), retention, and the route (list
     order, 404, testing room hidden).
   - A jar test plays a short real match through the wrapped factory and asserts the action log's
     `cmd` count equals the commands sent, and that the public stream's envelopes equal what the
     watcher channel emitted.

## §D — rebuild

Turn an action log back into a public stream, for a match whose stream has expired.

1. `canRebuild(header)` is true only when:
   - every seat is human;
   - `header.pin` and `header.bridge` equal the running server's (the jar and bridge it was played
     on);
   - the spec carries a seed.

   Otherwise false, with the reason logged.
2. `rebuild(matchId)` reads the action log and starts a match on a spare JVM through the same host
   factory with the header's spec. It sends each `cmd` once its seat reaches the recorded position:
   - a command recorded from the same position as the one before goes straight after it;
   - a reply waits for its ask;
   - a 30 s budget per position, after which it is a divergence: logged, and the rebuild fails.

   The resulting watcher envelopes, run through `createProjector(null)` exactly as the live
   channel does, are written as a fresh public stream and returned.
3. One rebuild at a time per server, queued behind the start queue so it never delays a real match.
4. Done when a jar test records a real match (C's wrapper), deletes its public stream, rebuilds it,
   and asserts the final board digest per seat equals the live run's.
