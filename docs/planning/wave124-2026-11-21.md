# Wave 124 — every animation in Magic goes through the motion kit

Protocol: `docs/handoff/w124.md` carries it. One manager, one sub-agent per
lane, all parallel, no shared files. Implementers commit and stop; the manager
verifies from artifacts, lands lane by lane, calls a lane landed only when the
deployed tree carries it.

The programme, the measurements and the kit's shape: `docs/planning/motion-unification-plan.md`.
**This wave starts only once M1 has landed** (the kit in `packages/ui-shell/src/motion/`, `Stage` with
its `defaultStage`, the `.animate(`/rAF ratchet). The tracker checks that M1's commit is on `origin/main`
before scaffolding.

## Size — checked before dispatch

**3 independent lanes**, each over an hour: board blows (A), board beats (B), off-board screens (C). They
share no file. The shared contract is the kit's API, which M1 fixes before the wave and no lane edits.
Each lane keeps its effects' exported signatures, so `numbers.ts`, the one caller of all of them, is
touched by nobody. That gives 3 lanes, 3 items, one long pole (B, `placed.ts` at 2,061 lines). There is
no engine or jar change. Target 3 h, hard stop 4 h.

## Acceptance — the operator's sentence, not the lane's

No operator-reported behaviour is in this wave. It is a refactor, and **its acceptance is that nothing a
player sees changes**. Each lane proves that on a claw with the e2e specs that a grep of `e2e/` finds for
the attributes, testids and classes its files set, not from a table. That grep's output and the run ids
go in the lane's note. A spec that needs changing is a sign the lane changed behaviour: stop and report.

## §A — board blows

The combat and spell effects are the kit's heaviest users of WAAPI: 8 direct `.animate(` lines, 22
`BEAT_ANIMATION_ID` sites and their own `quicken` calls. They are also the effects most often timed against
each other (a ram's contact feeds a crash, a crash a recoil).

1. Each `.animate(` becomes the kit's `animate(el, frames, opts, { tempo, reduced, stage })`. Passing `stage`
   registers the animation as a beat with NO hold (`stage.beat(r)`), the exact equivalent of
   `id: BEAT_ANIMATION_ID`. **Never `stage.track` a blow:** `track` is `noteBoardDrawing`, a hold on the pacer,
   and a ram, crash or bolt that tracked itself would add its own hold and change pacing. Hand-written guards and
   `quicken` calls go.
2. `prefersReducedMotion()` is read once, into the context, by whoever builds it, never inside an effect.
3. The particle claims in `crash.ts`/`quake.ts`/`projectile.ts` use the kit's pool through `ctx.particles`.
4. Keep every exported function's signature; build the `MotionContext` inside it from what it is given.
5. Made dead / deleted: every local `animate` guard and `quicken` call in these files; `quake.ts`'s
   leftover `Box`/`rel`/`shadow` copies if M1 left re-exports; `ram.ts`'s own `Box`/`Point`, replaced by the kit's.
6. Done when: `git grep -c '\.animate(' -- <A's files>` is 0 and `BEAT_ANIMATION_ID` has no hit in them.
   The ratchet baseline is lower by A's count. `pnpm run check` is green. Claw runs (grep-chosen,
   including `fx-effects`, `af413-weight`, `cp-lethal-blow`, `w69-attack-flash`, `fly-jump`) are green,
   with run ids in the note.
7. **Net diff:** A's non-test diff (`git diff --shortstat` over non-test files) is net negative. M1 landed
   about +72 lines of API on the understanding that this wave deletes more than that.

## §B — board beats

The beats the pacer waits on that are not blows: dice and coins (5 `.animate(`, 6 `BEAT_ANIMATION_ID` in
`dice.ts`), mills, P/T glints, the mana ring, and the CSS-driven departures and resolutions in
`departures.ts`/`placed.ts`. B is the long pole: `placed.ts` (2,061 lines) and `departures.ts` (777) start
their beats by attribute.

1. As §A steps 1–2 for `dice.ts`, `coin-flip.tsx`, `CoinToss.tsx`, `mill.ts`, `pt-impact.ts` and `mana-ring.ts`.
   Each `id: BEAT_ANIMATION_ID` becomes `stage` in `animate()`'s ctx (a beat, no hold). Only what calls
   `noteBoardDrawing` today (a die, a coin) becomes `stage.track(running, { root, after })`, which is that same hold.
2. Where `departures.ts`/`placed.ts` start a stylesheet beat on an element they own, register it with
   `stage.trackCss(el)` beside the attribute. The keyframe names stay as they are: `isBeat`'s prefix list
   still counts them until M3.
3. rAF loops in these files go through `everyFrame`, or `animate()` where they only interpolate.
4. Keep every exported signature.
5. Made dead / deleted: local guards, `quicken` calls and rAF loops in these files.
6. Done when: there is no `.animate(` or `requestAnimationFrame(` in B's files. The ratchet is lower by
   B's count. Every stylesheet beat B's files start is also `trackCss`-registered: the lane's note lists
   each one with its keyframe name, which M3 uses to delete the prefixes. `pnpm run check` is green.
   Claw runs (grep-chosen, including `mana-ring-once`, `w79a-arrival`, `played-card` and the pacing specs
   under the CPU quota) are green, with run ids in the note.

## §C — off-board screens

The screens around the board animate with no kit at all: `PackView`'s fuse, `SeatBar`'s seat steps,
`ModeRow`'s FLIP (4 `.animate(`), the gauntlet's arrival and reveal, the front page's featured match, the
lift and row drag. None cancels on unmount through one path, and none shares the board's reduced-motion
reading.

1. Each `.animate(` becomes `animate()` with a context built from the component: no stage beat (nothing
   paces on these), `reduced` from the kit, and `cancel` on unmount.
2. Each rAF loop becomes `everyFrame` (read, then write), or stays a single one-shot rAF where it only
   defers one `setState`. A one-shot that stays is listed in the note, with why, and the ratchet
   counts it.
3. Made dead / deleted: local `typeof … animate` guards and duplicate reduced-motion reads in these files.
4. Done when: `.animate(` in C's files is 0. The ratchet is lower by C's count. `pnpm run check` is
   green. Claw runs (grep-chosen, including `gauntlet-arrive`, `gauntlet-reveal`, `perf/draft`,
   `front-scroll-perf`) are green, with run ids in the note.
