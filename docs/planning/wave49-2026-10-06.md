## Settled — do not re-open

- **Two-click gestures wait for Forge.** Forge's server runs each client message on its own thread
  (`GameProtocolHandler.channelRead` → `FThreads.invokeInBackgroundThread`), so two acts sent back to back can be
  applied in either order. `match.ts`'s `afterMarked` is the one mechanism for that (X1, `979dc16`). Any new
  two-act gesture uses it. Do NOT route acts around the NetGameController in the bridge: the tracker tried it, and
  it broke yield prefs (`sendYieldUpdate` is not `setYieldPref`) and deadlocked a cast that waits for a target.
- **A wire property is additive and strict.** `packages/forge-wire`'s schemas are `strictObject`: a property the
  bridge starts sending without a schema entry fails every parse. The lane that adds one adds the schema, the
  adapter read and a fold test in the same commit.
- A behaviour lane proves each rule against real Forge itself (a Playwright or jar script per rule), evidence in
  `docs/planning/wave49-evidence/<lane>/`. Unit tests and screenshots are not proof of behaviour.
- New scenario files only, named `apps/server/src/play/scenarios/w49-<lane>-*.state`.
- **No version bumps, no ledger edits, no pushes in the wave.** The manager lands lanes on `w49` and reports
  READY; the tracker integrates, runs the full gate and pushes once.
- **The full gate before READY** (release-train lesson, 2026-10-05): every `*.jvm.test.ts` run serially with ONLY
  CI's env (jar, res, work dir — no `CARDTABLE_PLAY_PROBE` or other dev flags), judged against `ci.yml`'s
  `known_failing`/`known_flaky` lists by the judge step's own jq, plus the full forge-e2e with 0 SKIPPED. A suite
  that needs a flag sets it itself (`vi.hoisted`, see `w46-block-stop.jvm.test.ts`).
- No explanatory text on the board (operator, twice).
