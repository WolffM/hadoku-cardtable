# Wave 92 — platform phase 2, UI track: the shell kit becomes a package, and avatars stop reading watchparty's bundle

Protocol: `docs/handoff/w92.md` carries it. One manager, one sub-agent per lane (Sonnet), all parallel, no
shared files. Lanes report; the manager verifies from artifacts and lands lane by lane with `scripts/land.sh`
(`scripts/lanes/prove-and-land.sh` where a lane needs a claw proof).

**Why:** this is the UI half of phase 2 of the operator's platform plan (2026-11-06; the private artifact
https://claude.ai/artifact/Jm5BXZj9xLPnpMGDwLSTKu, with v2's HTML at
`~/.cache/cardtable-manager/handoff-2026-11-07/platform-plan-v2.html`). The plan: *"A new MIT packages/ui-shell
takes the parts that are already generic: chrome, trim, RoomShell and the embed mount; the stylesheet and
theme-init helpers, and usage counting; the settings frame and UI scale; the sound mixer, with its role registry
injected; the generic components. One APP_ID parameterizes the shell's storage keys, events and chat prefix. The
values do not change."* It also deletes local copies of fleet primitives (Modal, Reveal, reduced motion, theme
seed). And it replaces the client's read of watchparty's prefs cache row, plus the constants quoted from
watchparty-ui's minified bundle, with avatars resolved by userId. The server already resolves avatars that way
(`apps/server/src/people.ts`, `resolveAvatars`).

**Nothing here changes what a player sees.** The second game takes these parts from a package instead of copying
cardtable's.

## Size — checked before dispatch

**4 parallel lanes and 1 short sequential sweep.** The lanes' files are disjoint, and each is over an hour of work:
- **A** — chrome, trim, RoomShell and the embed mount;
- **B** — theme init, the stylesheet helper, the settings frame, UI scale and usage counting;
- **C** — the sound mixer, with its role registry injected;
- **D** — fleet primitives and avatars by userId. This is the long pole, because D is the only lane that changes
  behaviour under the DOM.

**Z**, the importer sweep, runs after A–D land. It rewrites every import of the old paths and deletes the
re-exports the lanes left behind. It owns the importer files, which no lane touches.

6 items in all, counting the manager's step 0. Target 3 h, hard stop 4 h.

**w91 runs at the same time** (platform phase 1). It owns server files, room-store, `scripts/layers/**`,
`docs/DECISIONS.md`, `docs/LICENSING.md`, `NOTICE.md` and `AGENTS.md`. This wave touches none of them; see "Owned by
nobody". Both waves land on main through the same `land.sh`, which takes its lock, so landings queue rather than
collide. Run e2e proofs **on claws only**; two waves at once overload hokon.

## Acceptance — no player-visible change

No operator-reported item is in this wave, so there is no RED-first two-browser spec. Each lane is accepted on
these proofs:
- **Every lane**:
  - the DOM contract is frozen, so `git diff` shows no `data-testid`, `data-*` or class name changed;
  - every localStorage key, custom event name and chat prefix the moved code writes is byte-identical. Prove it
    with a unit test that pins each key's literal value under `appId: 'cardtable'`;
  - the claw proof runs the e2e specs that `grep -rl` finds for the moved testids and the moved components'
    containers (memory: proof specs come from grep, not a table).
- **`packages/ui-shell` imports only `react`, `react-dom` and `@wolffm/*`.**
  `grep -rn "from '@hadoku/" packages/ui-shell/src` must print nothing, and the closing note shows it. Anything
  that needs `@hadoku/shared` or another Magic package stays in the app, or gets the value injected.
- **D**:
  - after D, no code reads watchparty's prefs cache key or any constant quoted from `watchparty-ui`'s `dist/`.
    Prove it with `git grep -n -E "watchpartyPrefsCacheKey|room-chrome\.js|0\.39\.8" -- apps/ui/src`, which must be
    empty;
  - a seat shows a viewer's chosen character from the server's roster. The e2e that covers avatars
    (`grep -rl avatar e2e/`) runs green on a claw.
- **Z**: `git grep` finds no import of the old paths, and every re-export stub is deleted.

No release note, since a player sees nothing.

   not copy or rewrite either: `apps/server/src/room/lobby.ts`'s `AVATAR_POOL` stays until rooms-protocol

   lines, with a "made dead / deleted" line in its note. Step 0's skeleton is exempt and counted once.
7. **No explanatory UI text**, and no UI design change. This is a move.

## §A — Chrome, trim, RoomShell and the embed mount

The chrome (`AppChrome`, `HeaderLinks`, `matchMedia`, `shell.ts`, `chrome.css`, `trim.css`) and the site trim are
already game-neutral apart from names: the app id, the display name, and the room key `cardtable-<id>`. The embed
mount (`embed/index.tsx`, `contract.ts`, `styles.ts`) mounts any React root into a shadow root under the fleet's
`GameBundleModule` contract.

1. `git mv` each file into `packages/ui-shell/src/{chrome,embed,trim}/`, then make each one take the app's
   identity from `appId()` or a prop, and nothing from `@hadoku/*`. Keep `EmbedApp.tsx` in the app. The mount
   takes the component to render, so the package does not import it.
2. Leave a one-line `export * from '@hadoku/ui-shell/<x>'` at every old path that has an importer outside A's
   files (`git grep -l`). Delete the old path outright where nothing imports it.
3. Add `configureShell({ appId: APP_ID })` at the top of `embed/index.tsx`.
4. Unit tests pin the literals: the room key prefix, every trim storage key, and every event name, under
   `appId: 'cardtable'`.
5. Done when:
   - `pnpm run check` is green;
   - the claw proof of the grep-selected specs (chrome, trim, the room page, the embed) is green;
   - `grep -rn "from '@hadoku/" packages/ui-shell/src/{chrome,embed,trim}` is empty.

## §B — Theme init, the stylesheet helper, the settings frame, UI scale and usage

`apps/ui/theme-init.ts` seeds `<html data-theme>` before first paint, as `@wolffm/themes`' `seedTheme` does. The
plan's "theme seed" is this file. `stylesheet.ts` builds the ordered sheet. `settings/Settings.tsx` is the fleet
`ConnectedSettings` frame with cardtable's tabs passed in, `ui-scale.ts` is the UI-scale setting (22 importers), and
`usage.ts` counts screens and controls by `data-testid`.

1. **Theme seed:** if `@wolffm/themes` exports `seedTheme` (or an equivalent) usable in `<head>`, delete
   `theme-init.ts` and call it. Otherwise move it to `packages/ui-shell/src/theme/` and say in the note which
   export was missing, so the tracker files the ask on the themes package.
2. Move the settings frame (taking its tabs as props: GameSettings and SoundSettings stay in the app), `ui-scale`
   and `usage` into the package. Usage posts to a URL it is given; it does not build `/cardtable/api/...` itself.
3. Add `configureShell({ appId: APP_ID })` first thing in `main.tsx`. Keep the CSS import order exactly as it is:
   the comment in `main.tsx` explains why it is load-bearing.
4. Unit tests pin the UI-scale key, the settings keys and the usage event name.
5. Done when:
   - `pnpm run check` is green;
   - the claw proof of the settings, UI-scale and usage specs is green;
   - a first-paint check shows no flash. The existing theme e2e covers it if `grep -rl data-theme e2e/` finds one;
     otherwise the note says how it was checked.

## §C — The sound mixer, with its role registry injected

`sound/index.ts` routes `playRole` through `mute.ts` (the player's mute and two levels) to `mixer.ts` (WebAudio,
planned by `mix.ts`). The roles come from `@hadoku/shared`'s `SOUND_ROLES`, and the assignments from
`/api/sounds/assignments` (`builderClient.ts`). The mixer, mute, queue and gain slider are generic; the role names,
the assignments client and the 27-colour matrix are Magic's.

1. Move `mixer.ts`, `mix.ts`, `mute.ts`, `queue.ts` and `GainSlider.tsx` into `packages/ui-shell/src/sound/`.
2. Split `index.ts`. The package gets `createSound({ roles, loadAssignments })` with `playRole`, `roleHandler`,
   `setRolePlayer`, and the screen- and match-music setters typed over the injected role list. The app's
   `sound/index.ts` becomes the place that calls it with `SOUND_ROLES` and `soundsClient`, and re-exports the same
   names, so no Magic importer changes.
3. `SoundSettings.tsx` stays in the app if it names roles; if it does not, it moves. Either way, the note says
   which.
4. Unit tests pin the mute and level storage keys, and prove that a role not in the injected list is refused by
   the type and plays nothing at runtime.
5. Done when:
   - `pnpm run check` is green;
   - the claw proof of the sound specs (`grep -rl -E "sound|mute|volume" e2e/`) is green;
   - `grep -rn SOUND_ROLES packages/ui-shell` is empty.

## §D — Fleet primitives, and avatars by userId (long pole)

**Primitives.** Cardtable has its own `Modal` and `Reveal` (with `reveal.css`), and `prefersReducedMotion` lives in
Magic's `play/motion.ts`.
1. For each: if `@wolffm/task-ui-components` (or `@wolffm/themes`) ships the same primitive, the app uses it and the
   local copy is deleted. Otherwise it moves to `packages/ui-shell/src/components/` (or `src/motion/`), and the note
   names the fleet package that lacks it, so the tracker files the ask.
2. `play/motion.ts` keeps `export { prefersReducedMotion } from '@hadoku/ui-shell/motion'`, and no other line of it
   changes.

**Avatars.** `room/avatar.ts` reads watchparty's prefs cache row from localStorage, and builds sprite URLs from
constants quoted out of `watchparty-ui`'s minified 0.39.8 bundle. It calls `createAvatarClient` only as a
fallback. The server already resolves every member's avatar by userId (`apps/server/src/people.ts`,
`resolveAvatars`, identity model R12), as watchparty's server does (`apps/server/src/rooms/avatars.ts` there).
3. Read the roster the server sends, and find where the viewer's own `avatarId` reaches the UI. If it is already on
   the roster, `selectedAvatarId` and `accountAvatarId` become reads of it. If it is not, `people.ts` adds it to
   what the server sends; D owns that file.
4. Delete `watchpartyOrigin`'s sprite use, `watchpartyPrefsCacheKey`, `selectedAvatarId`'s localStorage path, the
   `AvatarStore` seam, and every quoted constant. `avatarSquareUrl` takes its URL from `@wolffm/prefs-client/avatar`
   if it exports one. If it does not, the URL comes from the server alongside the id, and the note names the
   missing export.
5. Keep `normalizeAvatarId`'s and `avatarSquareUrl`'s signatures.
6. Done when:
   - the acceptance grep is empty;
   - `pnpm run check` is green;
   - the claw proof of the avatar specs (`grep -rl -i avatar e2e/`) is green;
   - the note lists every deleted export, with the line count made dead.
