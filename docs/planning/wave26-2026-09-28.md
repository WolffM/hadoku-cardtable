## §A — The table, blocked as drawn, and the mana pool drawn at all

Read `board-layout-2026-09-27.md` first; its table of regions is the target and
its percentages are what matter, not the pixels.

Three structural changes and one new thing:

1. **Four rows, hands outermost.** Opponent hand, opponent battlefield, the
   centre line, your battlefield, your hand. The two battlefields face each
   other; each hand is furthest from the middle.
2. **The piles stop being a column.** `.board .seat` currently reads
   `grid-template-areas: 'who field piles' / 'who hand piles'` (`board.css`
   ~:309, opponent mirror ~:324). The piles become the SECOND ROW of the left
   column — portrait beside the battlefield, graveyard beside the hand, mirrored

   this is that, as the operator's own geometry.
3. **`ZoneShell`'s panel and label both go** (`Board.tsx` ~:828-869): the border,
   the fill and the head. Keep the accessible name and keep `data-zone` —
   `e2e/play.spec.ts`, `table-fit.spec.ts` and `arrow.spec.ts` locate cards by
   it and those specs are B's, so breaking the attribute breaks another lane.
4. **Delete `.board__bar`.** It carries `data-testid="turn"`; the turn number
   lives on B's rail afterwards. Do not leave a hidden element behind to keep a
   spec quiet — B re-points the specs.
5. **Reserve the right gutter.** The rail, the controls and the log button float
   over the right end of the rows (B's), so a card must never come to rest under
   them. `.board__bar`'s own `padding-right: 11rem` was this trick for the

6. **Draw the mana pool.** The operator, 2026-09-27: *"if i tap the lands first
   then add mana to my pool, that should also work to pay for the spell"* — and

   on the view model, and draw it beside the seat's own portrait. Floating mana

7. Done when: `pnpm check` green; `Board.test.ts` pins the row order, the piles

## §C — The symbols are the fonts' now

The fonts landed on 2026-09-27 (`apps/ui/src/symbols/`, imported from
`styles.css`) and **nothing renders them yet**. Coverage was checked glyph by
glyph before they landed: every token `ManaPip` parses, and all 12 set codes the
nine eras use.

1. `ManaPip` keeps its token PARSER — `W/U` → hybrid, `2/W` → twobrid, `B/P` →
   Phyrexian — and changes only what it renders: `ms-<token>` classes instead of
   a letter in a disc. The parser maps 1:1 onto the font's class names; that is
   why this is a small change and not a rewrite.
2. A hybrid pip is **not** a single glyph — it is Mana's `.ms-cost` split system
   driving `::before` and `::after` against `--ms-split-top` /
   `--ms-split-bottom`. Use their classes; do not reimplement the split. A
   hand-rolled version renders `{W}` correctly and breaks `{W/U}` silently, which
   is exactly why the vendored CSS ships whole.
3. Add the set-symbol component: `ss-<code>` from the set code the card or era
   already carries. One component, so a set that has no glyph degrades to its
   code rather than to nothing.
4. An unrecognised token must still render as itself. `ManaPip`'s existing rule —
   *"a cost that silently drops a symbol is worse than an ugly one"* — survives.
5. **Do not change `ManaPip`'s or `ManaCost`'s public props.** Both are imported
   by `apps/ui/src/components/PoolView.tsx` and `apps/ui/src/draft/cardImage.ts`,
   and **neither file belongs to any lane this wave** — a prop change breaks the
   draft UI with nobody to fix it. `{ token }` and `{ cost, label }` stay as they
   are; only the rendered output changes. If you are certain a prop must change,
   stop and report.
5. Done when: `pnpm check` green; `ManaPip.test.ts` asserts a class per token
   family including hybrid, twobrid and Phyrexian, failing when reverted; and the
   closing note lists any token the fonts do NOT cover.

## §F — The room offers an era, and a drafted pool

Two things, and the second is the one that matters.

**Era set symbols.** Operator: *"constructed selections should show the set
symbols that are in that era."* The data is already there — `GET
/api/tables/formats` returns each era's `sets`, e.g. the 2012-08-11 era is
`SOM MBS NPH M12 ISD DKA AVR M13` — so this is C's set-symbol component on the
era rows and nothing more.

**A drafted deck can face a friend, and today it cannot.** This is the headline
gap wave 25 exposed, and it is not a regression so much as a hole nobody had
noticed: a room's pool is a `FormatId`, a human match must start from a room
(`routes.ts` ~:731 — *"a match against a person starts from a room"*), and a
drafted pool cannot be named as a room's pool. So for a project whose first line
is *"cube drafting + Magic play for a private friend group"*, the two halves have
never met. Wave 25 §A removed the per-seat `rules` that could have carried it —
which that wave's brief mandated, and which cost no working feature because the
UI only ever posted `{ room }`.

1. A room's pool becomes "a frozen Standard era **or** a drafted pool", not a
   `FormatId` alone. Keep the leader as the only one who moves it and keep the
   readiness-clearing that a pool change already does.
2. `startFromRoom` checks both decks against whatever the room's pool IS. Keep
   the privacy rule wave 25 §A kept: name the player and the pool, **never the
   card** — a drafted pool is hidden information until the draft is over, and
   naming someone's offending card reports their pool to whoever pressed the
   button.
3. A drafted pool belongs to WHOEVER DRAFTED IT. `gate.ts` resolves a pool by the
   caller's identity and that is the property the whole thing rests on: two
   players in one room drafted from the same pod, so "the room's drafted pool"
   must resolve per caller to their own pool, never to the leader's.
   **If that cannot be made to hold, stop and report rather than inventing a
   shared pool.**
4. The room screen offers it: a leader picking a draft this room's members
   actually drafted, and each player's deck dropdown offering their own drafted
   cards.
5. Done when: `pnpm check` green; a server test starts a human match from a room
   on a drafted pool with each seat's own pool resolved per caller, and another
   proves a player cannot load a deck from someone else's drafted pool — both
   failing when reverted, with counts. The note states plainly whether a human
   can now draft and play, end to end, or what is still missing.
