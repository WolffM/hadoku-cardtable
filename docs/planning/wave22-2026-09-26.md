### #5 and #8 were caused by a deploy, and the deploy was the tracker's

Not a Firefox bug and not a watchparty bug. The operator's console timestamps
are LOCAL (UTC-7), so their 08:14–08:16 session is **15:14–15:16 UTC**, which
lands between two redeploys of the tracker's own docs-only pushes:

- `15:11:27Z` redeploy of `6f1a2a8` (the w21 plan) → cardtable restarted `15:12:30Z`
- `15:16:29Z` redeploy of `1b0762b` (a retrospective) → cardtable restarted `15:17:02Z`
- watchparty restarted `15:16:42Z`, which is the `wss://hadoku.me/watchparty/ws/` errors

The server logged nothing between `08:00:32Z` and `14:49:09Z`, which is what
sent the first diagnosis down the wrong path until the local-vs-UTC offset
turned up.

**The mechanism is entirely ours:** `apps/server/src/index.ts` installs **no
SIGTERM handler at all**, and `play/host.ts`'s exit hook `SIGKILL`s every match
JVM when the process exits. So a deploy is: rebuild → `pm2 restart` → process
exits → every live match dies → `unknown-match`, and every socket drops.

**Already landed in this wave's branch** (the cheap half): `redeploy.yml` now
ignores `docs/**`, `**/*.md` and `.claude/**`, so a planning commit cannot end
a game. §E is the durable half.

### What is NOT the fix, so no lane spends the wave on it

The operator's instinct was *"ideally, old websockets are kept alive even if
redeploy happens"*. Keeping the OLD process alive to drain sockets means two
processes on one port sharing one on-disk room store — two writers, last one
wins. **That is not the cheap path and this wave does not take it.**

The client already survives a dropped socket: `forge:join`, snapshots, epochs
and resync are all built. What it cannot survive is the MATCH ceasing to
exist. §E closes that instead, which also fixes the 08:00 UTC nightly restart
that has been quietly ending games since the beginning.

### What we do and do not import from watchparty — settled, do not re-litigate

`@wolffm/rooms-server@0.39.5` is a **room-state library**: `state` (registry,
join/leave, seats, avatars), `emit`, `identity`, `rateLimiter`, `gc`. It does
not own a socket server and its whole type surface has no reconnect, resume or
persistence. The socket.io server, the match protocol and the JVM lifecycle
are **ours**. There is no upstream package that would have saved the match.

## §D — the mulligan you can actually answer

The operator mulliganed, was told *"return a card to the bottom"*, and the
cards were not clickable — they had to press **Auto**.

**The diagnosis, already made:** `ManipulateCardListPrompt` renders each card
as a `CardTile` with `draggable` plus tiny ↑/↓ buttons. The TILE ITSELF has no
click handler, so the obvious gesture — click the card you want on the bottom
— does nothing, and for a one-card London mulligan the ↑/↓ reorder model is
the wrong shape entirely.

1. A card in this prompt is **clickable**: clicking sends it to the zone the
   ask is asking for (bottom, or top when that is the ask).
2. Keep drag for reordering several; keep the buttons for keyboard.
3. When the ask wants exactly N cards moved, the prompt says which N are
   chosen and lets them be un-chosen — no hunting.

Done when: a London-mulligan fixture is answerable by clicking one card, the
reply on the wire is asserted, and drag still works for multi-card ordering.

## §E — a match that survives its server

The durable half of #5/#8.

1. **A SIGTERM handler.** Today there is none: the process exits and the exit
   hook `SIGKILL`s every JVM. On SIGTERM it should stop accepting NEW matches,
   tell seats what is happening, and exit cleanly.
2. **Matches outlive the process.** Spawn match JVMs **detached**, record each
   one's id/pid/port on disk beside its run dir, and on boot **re-attach** to
   any that are still alive instead of sweeping them. The client already has
   `forge:join` + snapshot + epoch + resync, so a re-attached match turns a
   restart into a reconnect rather than `unknown-match`.
   - The boot sweep (`run-dirs-swept`) must learn the difference between a run
     dir whose JVM is gone and one whose JVM is still running. It already
     spares a dir a live process has as its cwd — that is the seam.
   - A JVM with no server to talk to must not live for ever: give it a bounded
     orphan lifetime, and reap on re-attach when nobody rejoins.
3. **The client stops lying when a match really is gone.** `unknown-match`
   currently reaches the player as a raw string. It should say the match ended
   and offer the way back to the room.
4. **`redeploy.yml`'s path filter is already in this branch** — verify it, keep
   it, and note in the closing report that a docs push no longer deploys.

**This lane may be split.** If re-attach does not land, the SIGTERM handler and
the honest client message are worth landing alone — say so rather than
shipping half a re-attach.

Done when: a `pm2 restart` (or SIGTERM) during a live match leaves the match
running and the client reconnects to it; a match whose JVM is genuinely gone
tells the player so in words; and a docs-only push does not deploy.
