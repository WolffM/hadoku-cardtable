## Why this order

Stage 2b's goal is `apps/server` = the site only, with Magic in `games/magic/`. At 4faf3907b, `apps/server/src`
holds ~34.6k non-test Magic lines, ~12.4k platform and 147 site, with tangled at 0. Moving **the platform out
first** means the later Magic move can be a single directory rename (`git mv apps/server games/magic/server`,
then a thin new `apps/server` site), in which Magic's ~600 internal relative imports never change. Doing it the
other way round rewrites both sides twice.

## Settled

- **The new package:** `packages/game-server` (`@hadoku/game-server`, MIT, platform). It takes every
  `apps/server/src` file the layer map calls `platform`, keeping its relative path: `play/host.ts` →
  `packages/game-server/src/play/host.ts`. So platform-to-platform relative imports don't change. Its tests move
  with it. The name is a proposal: if a better one is obvious from the code (`service-kernel` already exists;
  read what it holds), take it and say why.
- **Magic and site files stay in `apps/server`** for now. Each import of a moved file becomes a package subpath
  (`@hadoku/game-server/play/host`), through the package's `exports`. That's a codemod, committed with the
  change.
- **No behaviour change.** Every unit, jvm and e2e test passes unchanged. The server's built bundle (esbuild)
  still bundles everything; the package is a workspace source package like `service-kernel` (read how that one is
  consumed: source or dist).
- **Licences:** the new package is MIT. Every file in it must already be header-free of GPL (the ratchet checks a
  platform file's header). `apps/server` stays GPL.
- **The UI's import of the server:** `apps/ui/src/play/**` imports `apps/server/src/play/host.ts` (w109's edge
  list). It becomes a `@hadoku/game-server` import, or a type moved to `packages/host-wire`/`platform-wire` if
  that's where it belongs. Say which.
- Delete what you replace. No re-export shims, no wave numbers in source, no version edits, no AI attribution.
  Never `/cutrelease` or `release.yml`, never `git stash`, never `pnpm install` in the worktree.
