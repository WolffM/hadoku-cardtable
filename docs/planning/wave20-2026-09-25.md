### Two policies the operator just settled — do not re-ask

**Auto-pass, refined (items 5+7, superseding w19's open call):** a seat with
**no legal action** passes automatically — including priority windows on the
stack, which is what makes a creature resolve without two humans clicking
(item 5). **Main phases always stop** — a turn is never auto-passed (item 7).
Full control restores every stop. Note for item 5: this does NOT change when
the stack resolves — resolution still requires successive passes under
Forge's rules; what changes is that a pass with no legal action behind it is
sent without asking. We still implement no rules.

**One answer is no question (items 4, 6):** a prompt with exactly one legal
reply is answered immediately — the ability chooser with one ability, the
mana payment with exactly one way to pay. `getAbilityToPlay` was deliberately
excluded from this in w19; that exclusion is now REVERSED for the
single-option case by this decision.

### Interfaces settled here

**B ↔ C — the rules own policy, the components own pixels.** B may add to
`rules.ts` a function of the shape `autoAnswer(ask): Reply | null` — the ONE
place "does this question answer itself" is decided. C's components call it
through `PromptShell` (or B wires it in `LiveBoard` before a prompt renders;
either is fine, pick one). C never embeds a policy decision, B never renders.

**A ↔ D — delegation, not imports.** D's inspector mounts through A's
`data-board-overlay` root and listens for pointer events on
`[data-board-card]` / `[data-card-id]` by DELEGATION at the board root. D
imports nothing from A's files except the DOM contract, and A adds no handler
for D. Enlarged art resolves through the w19 art-id table via
`@hadoku/carddata/art`.

## §A — the table reads like a table

1. **Rows by permanence type** (item 10): lands, artifacts, creatures — and
   an "other" row — each a labelled row within the battlefield's FIXED slot.
   Grouping is default ordering, not a cage: see 2.
2. **Drag to arrange** (item 10): a player drags a permanent within and
   between rows; the arrangement is theirs, persisted per match in the
   client, and survives a resync. Two affordances minimum: drag, and a
   "regroup" reset.
3. **The players' faces anchor** (item 11): OUR face and life bottom,
   OPPONENT'S top, opposite ends of the canvas. The stack keeps its centre
   slot. The operator likes the faces — this is placement only.
4. **The room table's rows** (item 3): the middot separators go; `ready` and
   `not ready` become a styled status (colour + shape, not colour alone);
   legality reads as a state, not a clause in a sentence.

Done when: grouping + drag + anchors hold at both sizes with the canvas
static (the table-fit proof extended to grouped layout); arrangement survives
a forced resync (test); the room table has no middot rows (screenshot-level
assertion in a test); `pnpm check` + lane e2e green.

## §B — turns that flow

## §D — the inspector

Hover (desktop) or long-press/click (touch) on any card the board, stack or a
prompt grid shows → an enlarged card: big art, name, types, P/T or loyalty,
and rules text IF the wire carries it (check what `CardView` sends; do not
invent a fetch). It follows the DOM contract, renders into the overlay root,
dismisses on leave, and never covers the player's own hand.

Done when: the inspector opens for a battlefield card, a stack item and a
prompt-grid tile in tests; it renders only data the seat was sent; keyboard
and pointer both dismiss it; nothing about it changes the canvas layout.
