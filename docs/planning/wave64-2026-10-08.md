# Wave 64 — consolidation: one pathway per fact, the duplicates deleted, every drift found named as a bug

Protocol: `docs/handoff/w64.md` carries it. One manager, one sub-agent per lane, all parallel, no shared
files. Implementers commit and stop; the manager verifies from artifacts (claws dispatches, never
`heavy.lock`), lands lane by lane with `scripts/land.sh`, and calls a lane landed when CI's `check` is
green on it and mgmt-api's log says `[deploy:cardtable] Verifying cardtable is serving <sha>` followed by
`Deploy completed`.

## The objective, in the operator's words (2026-10-08, after four reports on one path)

*"i have a feeling that a lot of the logic built here is just slapping bandaids on top and not addressing
the underlying problems. i feel like we're moving towards a slop mountain."* — *"do w64 as the
consolidation wave. the objective is to get rid of duplicate code and unify code pathways as best as
possible to uncover weird drifted code or self-created bugs."*

This wave adds no feature. Every commit either DELETES a second pathway, FOLDS two into one, or NAMES a
drift it found (as a ledger row, with the fix if it is small and in the lane's files). A lane that ends
with more lines than it started with has done the wrong thing. Behaviour changes only where a drift
was a bug, and each such change is its own commit with the operator's rule it restores cited.

## Settled — do not re-open in any lane

- **Delete, don't add.** A fold lands only with the deletion of the path it replaces in the same commit.
  A compat branch for a sender that no longer exists is deleted, not kept "to be safe" — both halves of
  every wire ship together.
- **Drift is a bug with a row.** Every behaviour difference a lane finds between two paths is written
  to `docs/planning/playtest-ledger.md`'s Incidents table by the manager (from the lane's note), with the
  rule it violates and the sha that fixes it. Found-and-fixed counts as the wave's output as much as the
  deletions do.
- **The journey is one state machine, designed before coded** (J). States per card on the sender: in hand
  → lifted (follows the pointer) → parked at a point (a question/X/target pending) → committed (on the
  stack or the battlefield) → landed; one presence message shape saying which; one receiver reducer; the
  placement travelling with the act (`forge:placement`, memory `placement-rides-with-the-act`). J's FIRST
  deliverable is a design artifact (like the stack design) with the state × event → drawing table on both
  screens, posted for the operator; J codes after the manager relays approval (or after 60 min with no
  objection, since the artifact restates rules the operator already gave: AD4, AD7, AC8, AE6, AE12).
- **No behaviour change hidden in a fold.** Each fold's commit message says "no behaviour change" and the
  pins of both paths are green before the deletion; a drift fix is its own commit.
- **The over-exports go dark.** knip's count per lane's files goes DOWN; a test that needs an internal
  reaches it through the public surface or a `*.internal.ts` the lane creates.
- Theme tokens only; no explanatory UI text; the house motion curve and 300 ms stay one constant.
