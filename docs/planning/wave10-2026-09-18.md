# Wave 10 — from "a match runs" to "you can play a game"

Protocol: `docs/handoff/w10.md`. One manager, four sub-agents in parallel, no
shared files. Gate baseline **1,523 passed / 61 files** (plus 2 gated on
`CARDTABLE_FORGE_JAR`). "Landed" = on `main`, CI green, redeploy green.

Wave 9 answered the question that gated everything: a human can be asked
something mid-match and answer it, 5.8 ms, board consistent afterwards. What
exists now is a match that runs, a board that renders it, and **fourteen prompt
components sitting on fixtures with nothing wired to them**. This wave closes
that gap and makes a match reachable from the product rather than from a test.

## Settled — do not re-open in any lane

- **One JVM per match.** O3 is closed and the answer is **forced**, not
  preferred: `FServerManager` is a per-JVM singleton and a second match dies at
  `FServerManager.java:276`. Do not try to host two matches in one JVM; upstream
  gave up on that too. Keep a **warm spare** so a new match does not wait 3.4 s,
  and keep `matchId` on every Node↔JVM message so the choice is reversible if
  the singleton is ever fixed.
- **The 15 prompt shapes are the whole set**, because `ProtocolMethod` is a
  closed enum. The client decides nothing; Forge computes all legality. If the
  engine appears to want a sixteenth, you have found something — **report it**.
- **The wire contract is done** (`@hadoku/forge-wire`: Tiers A/B/C, 41 of 58
  events modelled, 17 refused by name). A lane needing a refused event has a
  finding, not a licence to model it quietly.
- **Hidden information is measured against live data and must stay that way.**
  Wave 9: 142 secrets in Forge's raw stream, **0** emitted, per seat. Any change
  to projection or emit must keep that at 0 — and the test that proves it is
  gated on `CARDTABLE_FORGE_JAR`, so **run it deliberately**.
- **`forge/` is a submodule pinned at `2ad70eb4`.** Empty in a fresh worktree:
  `git submodule update --init --depth 1 forge`. **Never `git submodule deinit`
  in a worktree** — it unregisters forge in the deploy tree, which is the main
  checkout.
- Friend gate, D13/D15, D16/D17: unchanged.

## §A — Wire the other fourteen prompts

Lane C of Wave 9 built them against fixtures; lane B wired exactly one. This
lane connects the rest to the live match.

1. Each component already takes a payload and returns an answer under
   `@hadoku/forge-wire`'s schema. **Do not rewrite them** — wire them.
2. **`assignCombatDamage`, `order` and `sideboard` are the hard three**, and
   Wave 9's lane C was asked whether one of them is a wave of its own. Read its
   closing note before starting; if it said yes, believe it and say so again
   rather than quietly running long.
3. A prompt arrives mid-priority. **The board must not desync while one is
   open** — that is the failure mode worth testing, not whether the widget
   renders.
4. Every answer goes back through the same seam lane B proved. Do not add a
   second path.
5. Done when: each wired prompt round-trips against a real match (the
   `CARDTABLE_FORGE_JAR` tests), and the closing note lists which of the 15 are
   live, which are fixture-only, and why.

## §B — Constructed: choose a deck and start a match

The operator's stated goal — *"playing constructed with prebuilt decks, to
recreate standard formats from years past"* — becomes reachable here.

1. A screen: pick a format (Wave 6's `standardPoolAt`), pick a deck from the
   library (Wave 7 lane D's), start a match against another seat.
2. **Validate the deck against the format pool before starting**, and say
   *which card* fails and why. The validator exists; surface it.
3. Reuse the lobby that already exists for drafting. A second lobby is a second
   thing to keep correct.
4. This is where drafting and constructed converge: a drafted 45-card pool and a
   prebuilt 60-card deck are both just decks by the time a match starts. **Make
   that the same path** — if it is not, say why.
5. Done when: a person picks a format, picks a deck, and reaches a live match;
   an illegal deck is refused with the offending card named.

## §C — Match lifecycle: warm spare, crash, reconnect

Wave 9 starts a match. It does not yet survive anything going wrong.

1. **The warm spare.** O3 recommends keeping one JVM ready so a new match does
   not pay 3.4 s of Forge boot. Implement it, and measure the difference rather
   than asserting it.
2. **Crash.** A child JVM dies mid-match. The room must survive, both seats must
   be told, and the failure must not look like a hang. Wave 9's `exit(reason)`
   hook exists; use it.
3. **Reconnect.** A browser refresh mid-match must return to the same seat with
   the same board. The draft already does this via seat reservations and
   `classifySeq`; the same machinery applies.
4. **RSS.** O3 measured ~730 MB per separate JVM and that G1 does not give RSS
   back. Decide and document a ceiling on concurrent matches — at a handful of
   friends this is a comment, not a scheduler, but it should be a *deliberate*
   comment.
5. Done when: a killed JVM leaves the room alive and both seats informed; a
   refresh returns to the same board; and the warm-spare saving is a measured
   number.

## §D — Two humans, one draft, end to end

**PR-2 has been "built end to end, unproven with two people" for four waves.**
This is a measurement lane, not a build lane: it must not change product code.

1. Drive **two independent browser contexts** through one pod: join, pick, pass,
   wheel, finish. Playwright is already used in this repo.
2. Assert the thing that matters: **each context sees only its own pack and
   pool**, over whole serialised payloads, the way the engine tests do.
3. Exercise a refresh mid-draft in one context and assert the seat is held and
   the pool intact.
4. **If it does not work, that is the deliverable.** Four waves of tests say it
   should; nobody has watched two people do it.
5. Done when: an e2e test drives two contexts through a complete draft in CI-
   compatible form, or the closing note names exactly what stopped it.
