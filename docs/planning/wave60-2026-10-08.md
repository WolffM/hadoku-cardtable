## Settled — do not re-open in any lane

- **The hand reorder is a drag within the hand**, same slop and lift as a battlefield rearrange; the
  card glides into its new place over 300 ms (`cubic-bezier(0.3, 0.7, 0.3, 1)`, the house curve) and
  its neighbours slide, never jump (a FLIP on the hand's `<li>`s). Leaving the hand turns the press into
  the cast gesture exactly as today; nothing about casting changes.
- **The opponent sees the motion, never the card:** presence sends `handMove: { from: i, to: j }` (indices
  in the sender's hand order); the receiver animates the i-th BACK of their hidden hand to position j
  with the same glide. No id, no name — `play.spec`'s isolation check stays green.
- **A lifted card is the board's card size from the lift** (`--card-w` of the battlefield, not the hand's),
  so nothing shrinks later; the hand's own gap closes under it at once.
- **The banner's sentence is "Waiting for {name} to {verb} …"** from the open ask: `chooseSingleEntity` →
  "choose", `getChoices`/`chooseCardsForEffect` → "choose cards", `confirmAction` → "decide", a mana
  payment → "pay", with the host card's name when the ask has one: "Waiting for Hadoku to choose for
  Thirst for Knowledge…". Only when the viewer is not the one asked. The host card is on the stack (or
  resolving) by then: public. A hand card's name never reaches the other seat.
- **Mana symbols everywhere a cost or a produced mana is written:** the ability pop-up's options render
  through `RulesText` (`ManaPip`, the Mana font — D20); `aria-label` keeps the plain text for readers and
  specs. No other text in the pop-up changes.
- Theme tokens only; no explanatory UI text; delete what you replace (`made dead / deleted: …` per note).
  Comments explain the code; ids and lane letters go in commit messages only.
- Proof on the claws only (`git -C <worktree> push origin HEAD:refs/heads/verify/w60-<lane>`, then
  `gh workflow run forge.yml -R WolffM/hadoku-cardtable --ref verify/w60-<lane> -f only=e2e -f specs='…'`;
  never `--ref main`; delete the branch after; e2e tsc in the worktree BEFORE the push; `git -C` and
  absolute paths in every command that commits, pushes or dispatches; never `git add -A`). A plain
  `pnpm exec vitest run <path>` needs no jar env and no lock. Never `heavy.lock`.
- Landing: `scripts/land.sh` from the wave worktree after each verified lane; CI is the gate; closing
  notes landed, then `touch docs/handoff/w60.READY`. Evidence is text under `docs/planning/wave60-evidence/<lane>/`.

## §H — the hand reorders, seen by both (AD1)

1. `hand.ts`: a press on the viewer's own hand `<li>` (offered or not) starts a reorder: past the slop,
   the card lifts (board-sized — M's rule, read `--card-w` from the battlefield), the hand's gap follows the
   pointer (the `data-arrange-target` preview the row already has), and a release INSIDE the hand commits
   `withHandMove` and glides the card into place with a FLIP of the hand's `<li>`s (300 ms, the house
   curve). A release OUTSIDE the hand hands the press to the cast gesture as today (the card is already
   lifted: the handoff is a mode change, not a second press). Native HTML5 drag on hand cards is removed.
2. Presence: on commit, `handMove: { from, to }` goes with the next presence message; the receiver glides
   the i-th back of `[data-zone="hand"][data-owner="them"]` to j with the same motion (`presence.ts`).
3. `drag.spec.ts`: a hand card dragged within the hand and released ends up between its neighbours, with
   nothing sent to Forge (`actsSent` unchanged); dragged out, it casts as before (the existing cases).
   `presence.spec.ts`: bob sees a back in alice's hand move from position 0 to 2.
4. Mutation: drop the FLIP → `hand.test` FAILS; drop `handMove` → the presence case FAILS.
5. Done when: `hand.test`, `Board.test`, `presence.test`, `socket.test` fail when reverted; `drag`,
   `presence`, `played-card`, `w46-attack` green on a claw; `docs/planning/wave60-evidence/H/hand.md`
   records the gesture's rules and the deleted native drag.
